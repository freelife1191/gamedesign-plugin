# v0.2.0 — 대표 진입 스킬, 제품 간 인계, 승인형 업그레이드

<!-- github-release:start -->

## GitHub 게시용 요약

두 제품에 대표 진입 스킬이 하나씩 생겼습니다. 사용자는 세부 스킬을 먼저 고르지 않아도 됩니다. 제품은 선택한 경로와 역할을 작업 전에 영수증으로 남기며, 제품 간 인계와 설치본 업그레이드는 계약과 사용자 승인 아래에서만 진행됩니다.

### 주요 변경

- `game-design-studio`와 `game-design-career` 대표 스킬이 요청에 맞는 세부 스킬이나 오케스트레이터를 선택합니다.
- 작업 전에 케이스 ID, 소유 제품, 선택 경로, 불러온 스킬과 역할을 여섯 줄 라우팅 영수증으로 공개합니다.
- Studio와 Career 사이의 단방향 인계, 소유권 이전, 상대 제품 조회와 실패 동작을 계약으로 고정했습니다.
- `upgrade-game-design-suite`가 버전 차이와 실행할 명령을 먼저 보여 주고, 사용자 승인 뒤에만 설치 변경을 수행합니다.
- Windows의 한글·공백 경로, 경로 정규화, 인코딩, 임시 디렉터리와 브라우저 탐지 문제를 보완했습니다.
- Skillstead `svg-infographic/v0.10.0`, Archify `v2.15.0`, im-not-ai `v2.3.2`를 번들로 고정했습니다.

### 업데이트 안내

처음 설치할 때는 Git 마켓플레이스에서 Studio와 Career를 추가합니다. 기존 설치는 `upgrade-game-design-suite`를 실행해 변경 내용과 명령을 확인한 뒤 적용 여부를 선택하세요. Windows에서는 한글·공백 경로 설치 검증이 포함된 v0.2.0 이상을 권장합니다.

### 검증 요약

- 릴리스 게이트 `npm run validate:release`의 로컬 스테이지 통과
- 공식 플러그인·스킬 검증, 도식 렌더 드리프트와 포맷 스모크 통과
- 공개 당시 Ubuntu·Windows CI 11개 잡 통과
- 실행할 수 없는 검증은 성공으로 처리하지 않고 `SKIPPED`로 구분

### 알려진 제한

- 자동 업데이트는 제공하지 않습니다. 변경 내용을 확인하고 사용자가 승인해야 합니다.
- macOS Quick Look과 headless Chromium이 필요한 포맷 검증은 CI에서 실행하지 않습니다.
- 생성 결과의 재미, 흥행, 매출, 채용 성과, 법률 준수나 플랫폼 승인을 보장하지 않습니다.

## 상세 릴리스 노트

### 변경 배경과 목표

v0.1.x에서는 사용자가 제품 안의 여러 스킬 중 하나를 직접 골라 시작해야 했습니다. Studio와 Career에 각각 15개가 넘는 스킬이 생기면서, 기능을 찾는 부담과 여러 단계의 작업을 직접 이어 붙이는 부담이 커졌습니다. v0.2.0은 제품별 대표 진입점을 두어 자연어 요청에서 적절한 세부 경로를 고르고, 선택 결과를 작업 전에 공개하도록 바꿨습니다.

대표 진입점이 모든 일을 독점하지 않도록 경계도 함께 만들었습니다. 한 제품이 다른 제품의 책임을 자동으로 가져가거나, 인계가 끝난 뒤 조용히 소유권을 되찾거나, 업데이트 검사만으로 설치 파일을 바꾸는 동작을 금지했습니다. 설치와 CI 쪽에서는 Windows에서 실제로 드러난 경로·인코딩·프로세스 차이를 릴리스 차단 조건으로 올렸습니다.

### 기능별 상세

#### 대표 진입 스킬

각 제품에 사용자가 기억해야 할 대표 스킬을 하나씩 추가했습니다.

- Studio 대표 스킬: `game-design-studio`
- Career 대표 스킬: `game-design-career`

대표 스킬은 요청을 제품의 라우팅 레지스트리와 대조해 직접 실행할 세부 스킬이나 여러 작업을 묶는 오케스트레이터를 고릅니다. 한 장짜리 핵심 재미 정의처럼 범위가 좁은 요청은 직접 스킬로 보내고, 비전·경제·제작 로드맵을 함께 다루는 요청은 프로젝트 오케스트레이션 경로로 보냅니다.

v0.2.0 태그에는 Studio 원본 스킬 17개, Career 원본 스킬 16개가 포함돼 있습니다. v0.1.1과 비교해 각 제품에 대표 진입 스킬이 하나씩 늘었습니다.

#### 라우팅 영수증

대표 스킬은 분석이나 결과 작성 전에 선택 과정을 여섯 줄로 먼저 공개해야 합니다.

1. 요청에서 결정한 케이스 ID
2. 요청을 소유하는 제품 ID
3. 선택한 라우팅 경로
4. 실제로 불러온 스킬
5. 참여할 역할
6. 인계 여부와 다음 경계

필수 줄이 빠지거나 제품·경로·스킬 값이 레지스트리와 맞지 않으면 정상 실행으로 인정하지 않습니다. 영수증을 결과 뒤에 붙이거나, 상대 제품 조회가 필요한 인계를 조회 없이 완료했다고 쓰는 동작도 계약 위반입니다.

#### 세부 스킬과 오케스트레이터 선택

- 단일 산출물이나 범위가 명확한 요청은 해당 세부 스킬이 직접 소유합니다.
- 여러 분야의 판단과 결과 병합이 필요한 요청은 제품 오케스트레이터가 소유합니다.
- 전문가 검토 역할은 요청 범위에 맞춰 최대 세 개까지 선택하며, 역할별 지시와 결과 근거를 따로 남깁니다.
- 병합 결과는 역할별 발견 사항과 연결돼야 하며, 모델의 최종 문장만으로 검토가 끝났다고 간주하지 않습니다.
- 한 제품 안에서 끝나는 요청에는 불필요한 상대 제품 조회나 인계를 만들지 않습니다.

#### 제품 간 인계

Studio와 Career 사이의 협업은 `shared/suite-handoff` 단방향 계약을 따릅니다. 예를 들어 Studio에서 만든 기획서를 Career 포트폴리오로 전환하는 요청은 Studio가 공급자 자료를 준비한 뒤 Career로 한 번 인계할 수 있습니다.

- 인계 요청에는 요청 ID, 공급자 제품, 수신 제품, 산출물 경계와 반환 정책이 들어갑니다.
- 인계가 성립하면 현재 작업의 소유권도 수신 제품으로 넘어갑니다.
- 상대 제품이 설치되지 않았거나 비활성이라면 실제 인계를 했다고 보고하지 않고 제한 상태를 설명합니다.
- 다중 반환, 조용한 반환, 재귀 인계, 요청과 응답이 연결되지 않은 봉투는 거부합니다.
- 공급자는 자료를 제공할 수 있지만 수신 제품의 최종 승인이나 결론을 대신하지 않습니다.

#### 승인형 스위트 업그레이드

`upgrade-game-design-suite`는 설치 상태 확인, 공개 버전 비교, 변경 계획 제시, 사용자 승인, 설치 제공자 명령 실행과 사후 검증을 순서대로 수행합니다.

- Git 마켓플레이스 설치는 공개 태그와 현재 설치 버전을 비교합니다.
- 로컬 소스 설치는 원격 Git 명령을 실행하지 않고 현재 소스에서 다시 추가하는 경로를 사용합니다.
- 계획 단계에서 실행할 명령과 영향받는 제품을 보여 줍니다.
- 사용자 승인 전에는 플러그인 추가·교체·제거 명령을 실행하지 않습니다.
- 설치 디렉터리를 직접 수정하거나 공개 태그를 이동하는 우회 경로를 금지합니다.
- 적용 뒤에는 설치된 제품과 버전을 다시 읽어 계획과 결과가 맞는지 확인합니다.

#### Windows·인코딩·경로 보호

Windows CI와 한글·공백 경로 설치 왕복을 추가하면서 플랫폼별로 달랐던 가정을 정리했습니다.

- 패키지 텍스트의 UTF-8 BOM과 캐리지 리턴을 거부하고 LF 기준을 저장소에 고정했습니다.
- NFC 정규화와 대소문자 폴딩 뒤 같은 경로가 되는 파일을 차단합니다.
- 상대 경로 길이는 NFC 정규화 뒤 계산하며, Windows 제한을 넘기기 전에 빌드에서 거부합니다.
- 존재하지 않는 경로의 `realpath`, Windows 임시 디렉터리 판정과 플랫폼별 캐시 구분자를 보완했습니다.
- Windows 브라우저 탐지와 심링크로 선점된 예약 슬롯을 안전하게 거부합니다.
- 스냅숏 빌드, 이미지 설정과 프로젝트 기억 저장 경로가 운영체제별 홈 경로를 올바르게 사용하도록 수정했습니다.

#### CI와 설치 왕복

인증이 필요 없는 오프라인 검증을 여러 샤드로 나눠 Ubuntu와 Windows에서 실행합니다. 한글과 공백이 포함된 임시 경로에 두 제품을 설치하고, 재설치한 뒤, 선택 제거와 전체 제거를 거쳐 소스 상태와 임시 상태가 바뀌지 않았는지 확인합니다.

실행 환경이 없어 건너뛴 검증은 `PASS`가 아니라 `SKIPPED`로 기록합니다. 느린 테스트와 실제 멈춘 테스트를 구분할 수 있도록 시간 제한과 진단 출력도 보완했습니다.

#### 문서와 도식

### 설치 및 업그레이드

처음 설치할 때는 Git 마켓플레이스에 저장소를 추가한 뒤 필요한 제품을 설치합니다.

```text
/plugin marketplace add freelife1191/gamedesign-plugin
/plugin install game-design-studio
/plugin install game-design-career
```

설치한 뒤 새 세션을 열고 `game-design-studio` 또는 `game-design-career` 대표 스킬로 시작할 수 있습니다. 한 제품만 필요하면 해당 제품만 설치해도 됩니다.

기존 설치를 갱신할 때는 `upgrade-game-design-suite`를 사용합니다.

1. 현재 설치 출처와 제품 버전을 확인합니다.
2. 공개 태그와 번들 구성 요소의 변경을 비교합니다.
3. 실행할 명령, 영향받는 제품과 검증 계획을 읽습니다.
4. 적용하려면 명시적으로 승인합니다.
5. 새 세션에서 설치 결과와 대표 스킬 목록을 다시 확인합니다.

정상 업데이트에서는 먼저 제거할 필요가 없습니다. 제거 후 재설치는 손상된 설치를 복구하는 별도 절차로만 사용해야 합니다.

### 호환성과 운영

- Ubuntu와 Windows는 인증이 필요 없는 CI 샤드와 설치 왕복 검증 대상입니다.
- Windows에서는 PowerShell과 `%USERPROFILE%` 기반 경로, 한글·공백이 포함된 임시 경로를 고려합니다.
- macOS Quick Look과 headless Chromium이 필요한 `tests/formats/` 검증은 CI에서 건너뜁니다.
- Windows의 저장소 전체 검증 기준은 무조건적인 `npm test` 한 번이 아니라 CI에 정의된 오프라인 샤드입니다.
- 외부 모델 인증이 필요한 실제 대표 스킬 실행은 인증 상태와 실행 환경을 별도로 기록해야 합니다.
- 자동 업데이트는 없으며 업데이트 확인과 적용 승인은 분리됩니다.
- 공개 태그는 이동하거나 덮어쓰지 않습니다. 잘못된 배포는 새 패치 버전으로 수정합니다.

### 검증 근거

릴리스 당시 기록과 Git 이력에서 다음을 확인했습니다.

- `npm run validate:release` 로컬 릴리스 게이트 통과
- 공식 플러그인 검증기와 스킬 quick 검증기 통과
- 도식 렌더 드리프트와 대표 포맷 스모크 통과
- 공개 당시 Ubuntu·Windows CI 11개 잡 통과
- Studio 원본 스킬 17개, Career 원본 스킬 16개 확인
- 사용자 가이드 Markdown 162개 확인
- v0.1.1 이후 101개 커밋과 1,401개 변경 파일을 Git 이력에서 확인

릴리스 당시 실행할 수 없었던 스테이지는 `SKIPPED`로 기록했고, 현재 환경에서 새로 실행한 결과를 과거 릴리스 증거로 소급해 적지 않았습니다.
