# v0.1.0 — 게임 기획 스위트 초기 기준점

<!-- github-release:start -->

## GitHub 게시용 요약

Game Design Studio와 Game Design Career를 한 저장소에서 설치하고, 근거와 승인 기록이 남는 게임 기획·취업 준비 결과물을 만드는 첫 기준점입니다. 이 태그는 공개 배포 전의 역사적 기준점이며, 실제 공개 설치에는 다음 날 나온 v0.1.1 이상을 권장합니다.

### 주요 변경

- Studio에 게임 비전, 시스템, 콘텐츠, 경제, 라이브 운영, 제작 계획과 전문가 검토 흐름을 묶었습니다.
- Career에 직무 조사, 채용 공고 분석, 역기획, 포트폴리오, 면접과 성장 계획 흐름을 묶었습니다.
- 관찰·해석·제안을 구분하는 근거 처리 규칙, 승인형 용어 사전, 프로젝트 기억과 감사 기록을 도입했습니다.
- 문서 품질 프로필, 이미지 자산 수명주기, 컷씬 사전 시각화와 Skillstead 기반 도식화를 포함했습니다.
- 두 제품을 독립적으로 빌드하고 설치할 수 있도록, 같은 입력에서 같은 결과가 나오는 스냅숏 패키징 기반을 마련했습니다.

### 업데이트 안내

이 버전은 초기 이력을 보존하기 위한 태그입니다. 새로 설치하거나 기존 설치를 갱신할 때는 v0.1.1 이상을 사용하세요.

### 검증 요약

- 기준 커밋에 제품·공유 계약 테스트, 설치 스냅숏 검증, 사용자 가이드 검증과 UltraQA 기록이 포함돼 있습니다.
- 당시 공개 GitHub Release는 만들지 않았으므로 공개 다운로드와 배포 경로는 검증 범위가 아니었습니다.

### 알려진 제한

- v0.1.0은 공개 배포 전 기준점이며 v0.1.1이 이를 대체합니다.
- 생성 결과의 재미, 흥행, 매출, 채용 성과, 법률 준수나 플랫폼 승인을 보장하지 않습니다.
- 승인, 비용 지출, 외부 게시와 최종 품질 판단은 사람이 맡아야 합니다.

## 상세 릴리스 노트

### 변경 배경과 목표

이 릴리스는 게임 기획 업무와 게임 기획자 취업 준비를 서로 다른 제품 경계로 나누면서도, 같은 근거·승인·검증 원칙을 적용하기 위한 첫 기준점입니다. 단순한 프롬프트 모음이 아니라 요청을 정해진 경로로 보내고, 결과물을 구조화하며, 사용자가 확인할 수 있는 증거와 승인 기록을 남기는 플러그인 스위트를 목표로 했습니다.

저장소에는 Studio와 Career의 원본, 두 제품이 함께 쓰는 계약과 런타임, 독립 설치용 스냅숏, 사용자 가이드와 검증 도구가 함께 들어갑니다. 빌드 결과가 원본과 달라지거나 한 제품이 다른 제품의 내부 경로에 의존하면 검증이 실패하도록 경계를 세웠습니다.

### 기능별 상세

#### Game Design Studio

Studio는 아이디어를 한 번에 완성된 문서로 포장하기보다, 서로 검증 가능한 기획 단계로 나눕니다.

- 게임 비전과 핵심 재미를 정의하고, 목표 플레이어와 차별화 가설을 연결합니다.
- 코어 루프, 메타 루프, 규칙, 상태, 보상과 실패 조건을 시스템 기획으로 구체화합니다.
- 콘텐츠 구조, 진행, 경제, 밸런스, 라이브 운영과 제작 가능성을 같은 프로젝트 문맥에서 검토합니다.
- 역할별 검토 결과에는 출처와 판단 근거를 남기고, 병합 과정에서 충돌을 숨기지 않습니다.
- 문서, 프레젠테이션, SVG·PNG 도식 등 결과 형식별 품질 계약과 내보내기 전 검증 단계를 둡니다.

v0.1.0 태그에는 Studio 원본 스킬 16개가 포함돼 있습니다. 스킬은 비전·시스템·콘텐츠·경험·라이브 운영·제작·검토·시각화와 내보내기 같은 책임을 나눠 맡습니다.

#### Game Design Career

Career는 취업 준비를 막연한 조언이 아니라 확인 가능한 채용 근거와 반복 가능한 산출물로 바꾸는 데 초점을 맞췄습니다.

- 목표 직무를 세분화하고 채용 공고에서 반복되는 요구 역량과 도구를 추출합니다.
- 공고의 게시일, 출처와 관찰 내용을 보존하고, 해석이나 추천을 원문 사실처럼 섞지 않습니다.
- 역기획 주제를 관찰 범위와 증거에 묶고, 포트폴리오 문서의 문제 정의·분석·제안 구조를 관리합니다.
- 면접 질문, 답변 근거, 부족한 역량과 다음 학습 계획을 하나의 성장 흐름으로 연결합니다.
- 전문가 역할의 검토 결과는 정해진 형식으로 병합하며, 상충하는 판단을 임의로 지우지 않습니다.

v0.1.0 태그에는 Career 원본 스킬 15개가 포함돼 있습니다. 직무 매핑, 공고 조사, 역기획, 포트폴리오, 면접, 리뷰, 성장 계획, 시각화와 내보내기를 분리해 필요한 작업만 선택할 수 있게 했습니다.

#### 근거와 레퍼런스 인텔리전스

외부 자료와 프로젝트 내부 문서를 바로 결론으로 사용하지 않도록 수집·정규화·인덱싱·주장 검증 단계를 분리했습니다.

- 관찰한 사실, 그 사실에서 도출한 해석, 앞으로의 제안을 서로 다른 범주로 기록합니다.
- 출처가 없거나 오래된 채용 공고, 범위를 벗어난 역기획 관찰, 검증되지 않은 주장은 결과 경계에서 거부합니다.
- 한국어·영어 게임 기획 용어는 후보, 승인, 폐기, 대체 상태와 결정 근거를 갖습니다.
- 용어 변경은 기존 문서에 미치는 영향을 먼저 계산하며, 자동으로 본문을 다시 쓰지 않습니다.

#### 프로젝트 기억

프로젝트 기억은 대화 내용을 무제한 저장하는 기능이 아닙니다. 사람이 승인한 결정과 근거만 후보에서 승인 상태로 옮기고, 검색 결과도 원본 이벤트와 출처를 다시 확인한 뒤 제공합니다.

- 기억 항목은 후보·승인·만료·거부·분쟁·대체·오래됨 상태를 구분합니다.
- 원본 이벤트는 추가 전용으로 보존하고, 파생 색인이나 보기 파일을 판단 기준이 되는 원본으로 취급하지 않습니다.
- 프로젝트·워크스페이스·전역 범위를 나누고, 저장소 경계 밖으로 쓰지 못하게 경로를 제한합니다.
- 오래되거나 출처가 달라진 항목은 자동으로 다시 승인하지 않고 재검토 대상으로 돌립니다.

#### 문서 품질과 시각 자료

문서 유형별 품질 프로필과 템플릿을 두어, 결과가 형식만 그럴듯하고 내용 계약을 빠뜨리는 문제를 줄였습니다. 도식화는 저장소에 고정한 Skillstead 런타임을 사용하며 SVG 구조, 접근성 텍스트, PNG 렌더와 출처 기록을 검증합니다.

일반 이미지와 컷씬 이미지는 호스트에서 `image_gen`을 사용할 수 있으면 이를 우선합니다. 이미지 작업은 계획, 프롬프트 패키지, 비용 확인, 생성 승인, 결과 검토와 게시 상태를 분리하며 비밀 값이나 제공자 설정을 산출물에 포함하지 않습니다.

#### 컷씬 사전 시각화

컷씬 흐름은 장면과 샷을 먼저 설계하고, 캐릭터·배경·소품의 마스터 이미지를 연결한 뒤 생성 여부를 결정합니다. 각 샷은 연속성, 카메라, 감정, 비용과 생성 근거를 확인하며, 유료 생성은 사용자의 명시적 승인 전에는 실행하지 않습니다.

#### 빌드와 제품 경계

- 같은 원본에서는 Studio와 Career 설치 스냅숏이 항상 같게 생성됩니다.
- 대상 디렉터리 교체는 임시 스테이지, 검증, 저널과 복구 절차를 거칩니다.
- 제품 경계를 넘는 상대 경로, 심링크, 경계 밖 파일과 등록되지 않은 패키지 파일을 거부합니다.
- 독립 설치본에서도 필요한 공유 런타임과 문서가 빠지지 않았는지 검사합니다.
- v0.1.0에는 사용자 가이드 Markdown 157개와 제품별 설치·워크플로·스킬 안내가 포함돼 있습니다.

### 설치 및 업그레이드

v0.1.0은 공개 마켓플레이스 배포 전의 역사적 기준점입니다. 이 버전을 재현해야 한다면 태그가 가리키는 커밋 `d7a13bc10ac2ea4b868ae0bd6dd879329b8d6864`와 저장소 상태가 일치하는지 먼저 확인하세요.

일반 사용자는 v0.1.1 이상에서 제공하는 공개 설치 경로를 사용해야 합니다. v0.1.0에서 만든 프로젝트 산출물은 자동 변환하지 않으며, 새 버전으로 옮길 때 승인 기록·용어 사전·프로젝트 기억의 출처와 상태를 다시 확인하는 것이 안전합니다.

### 호환성과 운영

- 두 제품은 독립 설치를 전제로 하며 한 제품이 설치되지 않아도 다른 제품의 기본 흐름은 동작해야 합니다.
- Node.js 18 호환 경로를 테스트에 반영했지만, 이 태그는 공개 운영 환경 전체를 대상으로 한 호환성 보증 버전이 아닙니다.
- 외부 자료 조사, 이미지 생성, 파일 내보내기처럼 호스트 기능에 의존하는 작업은 해당 기능이 없으면 제한 상태를 밝혀야 합니다.
- 사용자 승인이나 외부 권한이 필요한 작업은 계획과 실제 실행을 구분하며, 실행하지 않은 작업을 성공으로 기록하면 안 됩니다.
- 별도 바이너리나 첨부 자산을 배포하지 않습니다.

### 검증 근거

이 기록은 `v0.1.0` 태그의 Git 이력과 태그 안에 포함된 테스트·보고서를 기준으로 정리했습니다.

- Studio 원본 스킬 16개, Career 원본 스킬 15개와 각 제품의 독립 패키지 경계를 확인했습니다.
- 사용자 가이드 Markdown 157개가 태그에 포함돼 있습니다.
- 제품·공유 계약, 근거 감사, 용어 사전, 프로젝트 기억, 이미지와 컷씬, 패키지 스냅숏을 다루는 테스트가 기준 커밋에 포함돼 있습니다.
- UltraQA와 시각 자료 검증 보고서가 저장돼 있지만, 당시 공개 GitHub Release를 만들지 않았으므로 원격 배포 자체는 통과 항목으로 기록하지 않습니다.
