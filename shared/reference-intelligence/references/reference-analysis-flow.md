# Reference analysis flow

Use the stages in this order: 0) brief, 1) role reference set, 2) evidence register, 3) Atlas selection, 4) system inventory without evaluation, 5) maps and loops, 6) priority, 7) deep dives, 8) comparison, 9) transfer proposals and verification queue.

Each role appears once: `direct-competitor`, `core-system-exemplar`, and `operations-monetization-comparator`. One game may fill several roles. When sources are offline, unavailable, not observed, or reference coverage is insufficient, record a limitation and open a verification item; do not infer a fact.

Each final analysis carries sorted `referenceContexts` (`contextId`, reference, version, platform). Evidence records carry the matching `contextId` and sorted `systemIds`; claims use the same system binding, and every claimed system must be covered by available evidence, so unrelated or partial evidence is never attached. The inventory preserves selected systems even when all evidence is unavailable or absent; those systems stay unknown and unscored until verified. Evidence IDs, source tiers, and claim kinds are preserved by the registry. A deep dive derives its claim kind from the least-certain available evidence; no available evidence is exactly `unknown`. Every comparison carries the matching `sourceSystemId` and exact deep-dive claim kind and evidence/reference/context/coverage trace. Unknown systems, orphan nodes, dangling connections, self-edges, missing input→process→output paths, undeclared cycles, and declared non-cycles are rejected by one shared graph validator before projection. A priority candidate is scored only when all seven dimensions are explicit integers from 1 through 5: relevance, player-experience impact, economy-progression impact, differentiation potential, evidence strength, uncertainty, and research cost. The first six dimensions rank candidates; lower research cost and then UTF-8 system ID break ties. Priority and deep-dive arrays are both in contiguous rank order (`1..N`), never lexical system-ID order.

Transfers are proposals only: `adopt`, `adapt`, `reject`, or `hold`. Every transfer binds its exact deep dive. Evidence/reference/context IDs and computed available-reference coverage are recomputed from the authoritative registry, contexts, and reference set—caller-provided trace must match exactly. Every transfer remains `pending-review` with `validationState: not-run`, nonempty sorted project constraints, risks, and validation steps; this analysis never mutates a system specification. `glossaryReceipt` is `null` before Task 4—no placeholder receipt is fabricated. Use `hold` for insufficient independent evidence or reference coverage. The verification queue contains exactly the required unavailable-evidence (`verify-evidence-${evidenceId}`) and insufficient/unknown-dive (`verify-system-${systemId}`) items, including their exact question, state, and evidence IDs; it is empty when no real pending item exists and no fallback item is fabricated.

`writeReferenceAnalysisWorkspace` writes fixed root artifacts plus safe-ID-derived `system-maps/` and `deep-dives/` children. The evidence register contains both contexts and evidence as canonical JSON-compatible YAML. It precomputes and size-checks every document before creating a directory or writing a file; every artifact is limited to 2 MiB and then written through the safe writer.
