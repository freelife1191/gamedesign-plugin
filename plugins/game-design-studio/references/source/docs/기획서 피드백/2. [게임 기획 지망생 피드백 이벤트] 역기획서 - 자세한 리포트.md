게임 기획서, 특히 역기획서 작성 시 가장 중요한 것은 무엇일까요? 단순히 시스템을 설명하는 것을 넘어, **기획 의도를 깊이 있게 분석하고 논리적으로 풀어내는 능력**을 보여주는 것이 핵심입니다.
## 1. 게임 기획서, 특히 역기획서 작성 시 핵심 역량 분석


### 1.1. 역기획서의 본질: 시스템 설명 넘어 기획 의도 분석 능력 어필
1. 역기획서 작성 시 가장 중요한 것은 단순히 시스템을 설명하는 것을 넘어, **기획 의도를 깊이 있게 분석하고 논리적으로 풀어내는 능력**을 보여주는 것이다. 
2. 이는 신입 기획 지망생의 포트폴리오에서 가장 효과적으로 자신의 역량을 어필할 수 있는 부분이다. 
3. 합격을 위해서는 평균적인 신입 기획 지망생의 수준을 넘어서야 하며, 이를 위해 기획 의도 파트에 집중하는 것이 가장 효과적이다. 
4. 기획 의도 파트에서는 다음과 같은 구체적인 내용들을 작성해야 한다. 
  1. **시스템의 목적 및 이용 대상**:
  - 어떤 형상, 어떤 수준의 플레이어가 어떤 맥락으로 어떤 목적을 가지고 이 시스템을 주로 이용하도록 할 것인가에 대한 설명이 필요하다. 
  2. **시스템의 위상 및 차별점**:
  - 게임 내 여러 성장 요소 중 해당 시스템이 갖는 비중, 위상, 그리고 다른 시스템과의 차이점은 무엇인지 명확히 해야 한다. 
  3. **플레이어 경험 및 감정**:
  - 플레이어가 이 시스템을 통해 얻게 되는 경험과 감정은 무엇인지 구체적으로 제시해야 한다. 
  4. **플레이어의 의사결정 및 도전**:
  - 플레이어가 시스템을 사용할 때 어떤 의사결정을 내리고 어떤 도전을 하게 될지에 대한 분석을 포함해야 한다. 
  5. **시스템의 의미 및 플레이어 심리**:
  - 랜덤으로 장비의 추가 옵션을 부여한다는 것이 어떤 의미를 지니는지, 플레이어에게 어떤 충동을 불러일으키는지에 대한 분석을 담아야 한다. 
  6. **유사 시스템과의 비교**:
  - 다른 미니 드라이브 시스템과 같이 비슷한 시스템이 존재할 경우, 그 시스템들과 어떤 차이점이 있는지, 그리고 그 차이점으로 인해 플레이어들이 어떤 감정을 갖게 될 것인지에 대한 내용도 포함할 수 있다. 
5. 기획 의도에 대한 분석력, 통찰력, 게임 이해도를 어필하는 것이 중요하다. 
6. 왜 이 시스템을 만들어야 하는가뿐만 아니라, 왜 이 시스템을 **이런 방향으로** 만들어야 하는가에 대한 상세한 기획 의도와 그에 대한 빌드업이 전반에 잘 녹아 있어야 한다. 


### 1.2. 기획서의 구조 및 명칭 설정: 가독성과 이해도 향상 전략
1. **목차 구성의 고정관념 탈피**:
  - 많은 신입 지망생들이 기획서의 전체적인 순서를 '시스템, UI, 테이블' 또는 '게임 UI 시스템 테이블' 순서로 배치해야 한다는 고정관념을 가지고 있다. 
  - 하지만 이는 현업에서 사용하기에 매우 불편한 전개 방식이다. 
  - UI 시스템과 테이블은 서로 연결되어 있기 때문에, 기능 하나를 구현할 때마다 UI 페이지와 테이블 페이지를 번갈아 찾아봐야 하는 불편함이 발생한다. 
  - 따라서 하나의 큰 시스템을 작은 시스템 단위로 나누고, 그 안에서 '시스템 - UI - 테이블' 순서로 전개하는 것이 좋다. 
  - 문서 전체를 '시스템 - UI - 테이블' 순서로 전개하는 것은 바람직하지 않은 방식임을 인지해야 한다. 
2. **직관적인 명칭 사용**:
  - 문서의 첫인상이 되는 페이지(목차 등)에서는 게임의 고유 명사보다는 해당 시스템이 무엇인지 직관적으로 이해하기 쉬운 이름을 사용하는 것이 문서 전체를 이해하는 데 도움이 된다. 
  - 예를 들어, '세공'보다는 '**랜덤 옵션 부여 시스템**'과 같은 명칭이 더 이해하기 쉽다. 


### 1.3. 시스템 규칙 설명: 표 활용을 통한 가독성 및 효율성 증대
1. **표 활용의 중요성**:
  - 시스템 규칙을 설명할 때는 표를 적극적으로 활용하여 중복된 문장을 줄이고, 필요한 내용을 빠르게 찾을 수 있도록 가독성을 높여야 한다. 
  - 표로 정리하면 작업자가 구현에 필요한 내용을 체크리스트로 활용할 수 있으며, 필요한 정보를 항목별로 빠르게 찾을 수 있어 효율적이다. 
2. **기획서 작성 시 독자 배려**:
  - 기획서를 쓸 때는 항상 독자를 배려하는 마음을 가져야 하며, 이는 결과물의 퀄리티 향상으로 이어진다. 
3. **규칙 설명의 정확성 및 상세화**:
  - 옵션 수치가 완전 무작위로 부여되는 것이 아니라, 세공 옵션 테이블에서 설정한 기준과 수치 범위 내에서 랜덤으로 부여되는 것이 맞다. 
  - 세공 소모 골드량이 어떤 규칙으로 정해지는지, 기획자가 어떻게 이 값을 설정할 수 있어야 하는지에 대한 내용도 규칙 설명 페이지에 포함되어야 한다. 
  - 이러한 소모 골드량 설정 테이블이 있다면, 해당 테이블을 참조한다는 내용을 명시하고 설명을 추가해야 한다. 
4. 게임 컨피규레이션** **테이블** 활용**:
  - 시스템 이용 가격이 특별한 규칙 없이 변동되는 경우, 별도의 테이블을 만들기보다는 테이블로 제어할 필요성이 있는 모든 것들을 넣는 '**게임 컨피규레이션**' 테이블에 포함하는 것이 적절하다. 
5. **가독성 높은 규칙 설명**:
  - 규칙 설명 시 표를 활용하여 필요한 내용을 빠르게 찾을 수 있도록 해야 한다. 
  - 현재 작성된 내용이 너무 의식의 흐름대로 작성되어 있어 가독성이 떨어진다. 
  - 다른 규칙 페이지들도 마찬가지로 표 활용을 통해 가독성을 높여야 한다. 


### 1.4. 플로우 차트 활용 및 한계점: 불필요한 복잡성 지양
1. **플로우 차트 명확성 확보**:
  - 플로우 차트에서 '세공 옵션 시작'과 '세공 옵션 종류'와 같은 용어는 무엇을 의미하는지 명확하지 않으므로, 무엇을 설명하기 위한 플로우 차트인지 페이지에 함께 작성하고 '플로우 차트 시작', '플로우 차트 종료' 등으로 용어를 통일하는 것이 좋다. 
2. **플로우 차트의 불필요성 판단**:
  - 규칙이 세공 옵션 테이블을 통해 정의되는 경우, 플로우 차트를 그리는 것은 불필요하다. 
  - 이러한 경우, 플로우 차트 대신 세공 옵션 테이블의 어떤 컬럼을 어떤 식으로 참조하여 결과에 반영할 것인지에 대한 설명을 작성해야 한다. 
3. **플로우 차트의 적정 길이**:
  - 플로우 차트가 한 페이지를 넘어간다면 뭔가 잘못되었다는 의심을 해야 한다. 
  - 길고 복잡한 플로우 차트는 웬만해서는 나오지 않으며, 이는 차트의 범위를 너무 넓게 잡았거나, 불필요한 정보가 너무 많이 포함되었거나, 테이블과 설명으로 해결 가능한 부분을 차트에 넣었을 가능성이 높다. 
4. **플로우 차트 관련 추가 학습**:
  - 플로우 차트 작성에 대한 더 자세한 내용은 유리링 강의 영상을 참고할 수 있다. 


### 1.5. UI 기획서 작성 시 주의사항: 사용 설명서가 아닌 기획 의도 파악에 집중
1. UI 레이어 구조** 작성의 불필요성**:
  - 기획자가 기획서에 UI 레이어 구조를 작성하는 경우는, 레이어 구조에 큰 의도가 있지 않는 한 거의 없다고 볼 수 있다. 
  - 신입 지망생 기획서에서 UI 레이어 구조를 작성한 페이지가 자주 보이는데, 이는 불필요한 페이지이므로 빼는 것이 좋다. 
2. 인게임 사진** 대신 **UI 피그마** 활용**:
  - 역기획서를 작성할 때는 인게임 사진을 그대로 사용하는 것보다, 인게임 UI 피그마와 같은 툴을 활용해 그린 사진을 넣는 것이 좋다. 
  - 이는 실무에서도 기획서 작성 시 UI를 이해하기 쉽게 그릴 수 있다는 역량을 함께 어필하기 위한 목적이다. 
3. **UI 역기획서의 본질**:
  - UI 역기획서의 목적은 이미 있는 UI를 어떻게 사용하는지 설명하는 것이 아니라, 각 UI 항목에 담긴 기획자의 기획 의도를 추측하고 답을 맞추는 것이다. 
  - 전반적으로 UI 사용 설명서 느낌이 강한 것은 지양해야 한다. 
4. **기획 의도 중심의 재구성**:
  - 왜 이런 UI를 제공하는지, 왜 이런 형태로 설계했는지 중심으로 재구성이 필요하다. 
  - 예를 들어, 해당 인터페이스를 제공해야 하는 이유, 왜 이런 형태로 제공해야 하는지, 어떤 점에서 편리하다고 생각하는지와 같은 기획 의도를 포함해야 한다. 
5. **UI 엘리먼트 상세 규칙 포함**:
  - 토글 버튼의 기본 값은 On 또는 Off 중 무엇으로 제공할 것인지, 그리고 왜 그렇게 할 것인지에 관한 UI 엘리먼트의 상세 규칙도 포함되어야 한다. 
  - 기획 의도 또한 추가되어야 한다. 
6. **UI 구성 요소 관련 추가 학습**:
  - UI 구성 요소에 대한 더 자세한 내용은 유리링 강의 영상을 참고할 수 있다. 


### 1.6. 문서 작성 효율화: 불필요한 페이지 축소 및 테이블 활용 전략
1. **공용 시스템 문서화 지양**:
  - 예외 사항 알림 문구, 토스 스위치처럼 게임의 공용 시스템을 문서에서 다루는 것은 불필요하다. 
  - 이는 페이지 낭비로 이어질 수 있다. 
2. **콤팩트한 문서 구성**:
  - 불필요하거나 내용이 중복되는 페이지는 최대한 줄여서 콤팩트하게 만들어야 한다. 
  - 이는 독자 입장에서 읽기 편하고 필요한 내용을 빨리 찾을 수 있도록 돕는다. 
3. **테이블 설계의 이유 명시**:
  - 기획서에 테이블을 넣을 때는 각 테이블을 만들어야 하는 이유와 이러한 방식으로 만들어야 하는 이유를 함께 설명해야 한다. 
  - 테이블 설계에 대한 더 자세한 내용은 유리링 강의 영상을 참고할 수 있다. 
4. **예시 데이터 해석 포함**:
  - 예시 테이블을 넣을 때는 예시 데이터에 대한 해석도 함께 작성해야 이해하기 쉽다. 
  - 현재로서는 무엇을 위한 테이블인지, 어떤 식으로 게임에 반영되는 것인지 이해하기 어려운 부분이 많다. 
5. **테이블 연계성 및 설계 의도 강조**:
  - 이 테이블을 왜 설계해야 하는지, 게임에 어떻게 반영되어야 하는지, 시스템과 어떻게 연계되는지, 왜 이런 구조로 설계되어야 하는지와 같은 기획 의도가 테이블에 데이터를 입력하는 것보다 더 중요하다. 
  - 이 부분을 보강하면 실무에 강점이 될 기획서로 발전시킬 수 있다. 


### 1.7. 기획서 전반의 가독성 및 실무 역량 어필 방안
1. **총평 및 아쉬운 점**:
  - 제출된 문서를 통해서는 지원자가 어떤 역량을 갖고 있는지 알기 어렵다는 점이 아쉽다. 
  - 지망생들의 전형적인 기획서 작성 습관(목차 구성, 식상한 기획 의도, UI 레이어 구조 등)이 문서에 나타나고 있다는 점도 아쉽다. 
  - 전반적으로 의식의 흐름대로 작성된 줄글이 많아 가독성이 좋은 편은 아니다. 
2. **실무 역량 어필 방안**:
  - 역기획서로 본인의 역량을 어필하려면, 기획 의도 내용을 대폭 보강하여 분석력, 통찰력, 게임 이해도를 어필해야 한다. 
  - 또는 UI와 그림, 상세하고 가독성 좋은 규칙 설명을 통해 실무 능력을 어필해야 한다. 
  - 현재는 이 두 가지 중 어느 하나도 잘 잡지 못하고 있는 상태이다. 
3. **가독성 향상을 위한 노력**:
  - 독자가 원하는 내용을 쉽고 빠르게 찾을 수 있도록 하는 방법에 대한 연구가 지속적으로 필요하다. 
  - 이는 기획서를 많이 쓸수록 느는 부분이므로, 일단 많이 써보는 훈련을 하는 것이 좋다. 
4. 테이블** 이해도 및 문서 작성 방식**:
  - 테이블 이해도는 신입 기획자로서 나쁘지 않은 수준이며, 독학으로 이룬 성과라는 점을 고려하면 더욱 그렇다. 
  - 하지만 문서에서 테이블을 다루는 방식은 아쉬운 점이 있다. 
5. **합격 가능한 기획서 수준**:
  - 현재 문서의 수준은 학원 출신 지망생 평균치에 가까우며, 독학하는 것 치고는 꽤 잘 아는 편이다. 
  - 하지만 합격이 가능한 기획서 수준에는 아직 많이 부족하다. 
6. **성장 가능성**:
  - 독학으로 이만큼 끌어올린 점을 봤을 때, 앞으로 조금 더 공부하고 노력하면 충분히 가능성이 있는 지원자이다.
