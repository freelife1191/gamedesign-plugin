게임 시스템 기획, 무엇부터 시작해야 할까? 복잡한 시스템은 기능 단위로 분해하고 각 기능의 입력, 출력, 규칙을 정의하는 것이 핵심이며, 이는 햄버거 조립처럼 핵심 재료부터 만드는 것과 같습니다.
## 1. 게임 시스템 기획의 핵심: 부분과 전체 이해하기
게임 시스템 기획은 복잡해 보이지만, 기능 단위로 분해하고 각 기능의 입력**, 출력, 규칙**을 정의하는 것이 핵심이다. 이는 마치 햄버거를 만들 때 핵심 재료부터 준비하는 것과 같다.


### 1.1. 시스템 기획, 무엇부터 시작해야 할까?
초보 기획자가 시스템 기획을 어려워하는 이유는 막막함 때문이다. 펫 시스템을 예로 들면, 펫 획득, 관리, 성장 등 떠오르는 기능은 많지만 어디서부터 시작해야 할지 알기 어렵다. 


- **잘못된 접근 방식**: 유저 입장에서 보이는 인터페이스 흐름대로 기획을 시작하는 것은 비효율적이다. 예를 들어 전략적 팀 전투 모드를 만들 때 매칭 화면부터 기획하는 것은 햄버거 가게에서 포장지부터 접는 것과 같다. 
- **핵심은 햄버거 조립**: 햄버거를 주문받았을 때 포장지보다 햄버거 조립이 더 중요하듯, 시스템 기획도 완성품의 비전을 보되 **핵심 재료(기능)**부터 만드는 것이 중요하다. 
- **재료 파악의 중요성**: 완성품을 분해하면 필요한 재료(기능)가 눈에 들어온다. 이번 시간에는 하나의 큰 시스템을 재료 단위로 분해하는 방법을 배운다. 

### 1.2. 시스템은 작은 부분들의 집합체
시스템은 각자의 규칙을 가지면서도 다른 부분과 상호작용하는 여러 **부분들의 집합체**이다. 


- **부분의 역할**:
  - **공격 규칙**: 캐릭터가 공격 능력을 사용했을 때 일어나는 규칙. 
  - **데미지 계산 규칙**: 공격이 대상에게 적중했을 때, 공격력과 방어력을 기반으로 데미지를 계산하여 체력을 감소시키는 규칙. 
  - **사망 규칙**: 체력이 0이 되면 사망 처리를 하고 사망 모션을 취한 뒤 필드에서 제거되는 규칙. 
- **시스템의 형성**: 이러한 부분들이 모여 **전투 시스템**과 같은 하나의 시스템을 이룬다. 
- **상호작용의 규칙**: 부분들은 서로 경계를 넘어 상호작용하며, 이 과정에도 규칙이 존재한다. 상호작용을 통해 정보와 리소스가 전달되고, 이는 해당 부분의 상태에 영향을 미친다. 
  - 예시: 공격 규칙에 따라 적중이 성공하면, 데미지 계산 규칙에 사실을 전달하여 데미지를 계산하고, 남은 체력이 0이면 사망 규칙에 사실을 전달하여 사망 판정을 내린다. 
- **시스템 간 **상호작용: 시스템을 구성하는 부분들은 다른 시스템의 부분 또는 전체와도 상호 작용할 수 있다. 
  - 예시 (양코 대전쟁): 공격 규칙, 데미지 계산 규칙은 타워 체력 규칙과 상호작용하며, 체력이 0이 된 타워가 적 타워인지 유저 타워인지에 따라 승리 또는 패배 규칙이 적용된다. 

### 1.3. 시스템 기획자의 역할: 기능 단위 분해
시스템 기획자는 각 부분의 입력** 처리, 출력 규칙, 그리고 **상호작용** 규칙**을 기획해야 한다. 이를 위해 시스템을 **기능 단위의 부분**으로 나눠 볼 줄 알아야 한다. 


- **잘못된 기능 분해 예시 (블루 아카이브 총류의 상점)**:
  - 일반 상점, 엘리그마 상점, 총력전 상점, 전술 대회 상점, 유저 인터페이스 상점, 알바생 캐릭터 등은 기능 단위 분해가 아니다. 
  - 상점 종류가 4개라고 4개로 나누는 것은 아직 유저의 시야를 넘지 못한 것이다. 
- **올바른 기능 분해 (동사 기준)**:
  - 상점 시스템은 **"뭔가를 지불하면, 뭔가를 준다"**는 구조로 파악해야 한다. 
  - 핵심 시스템:
  - 상품 구매 시스템 (재화를 지불하면 상품을 준다) 
  - 상품 판매 시스템 (상품 기획자가 판매할 물건을 세팅) 
  - **필요 시스템**:
  - 상점 인터페이스, 각종 팝업 인터페이스, MP3 대사 출력 시스템 
  - 구매 수량 선택, 보유 수량 계산, 가격 계산 시스템 
  - 상품 다중 선택 시스템 (편리 기능) 
  - 구매 횟수 제한 시스템 (한정 상품) 
  - 랜덤 상품 출력 시스템, 랜덤 상품 목록 갱신 시스템 (랜덤 상품 판매 상점) 
- **시스템과 콘텐츠의 구분**: 모든 상점은 동일한 **구매 시스템과 판매 시스템**으로 구성될 수 있다. 판매 물품이나 요구 재화의 종류가 다른 것은 시스템의 차이가 아닌 콘텐츠의 차이이다. 
- **시스템 조합**:
  - 구매 횟수 제한 시스템과 상점 시스템이 조합되면 구매 횟수가 제한된 상점이 된다. 
  - 랜덤 판매 시스템과 상점 시스템이 조합되면 일정 시간마다 상품이 랜덤으로 갱신되는 상점이 된다. 
  - 시스템의 부분들은 여러 방식으로 조합되어 다양한 콘텐츠를 만들어낸다. 
- **재활용의 중요성**: 새로운 상점 시스템을 또 기획할 필요 없이, 이미 만들어진 시스템(상점 시스템, 랜덤 판매 시스템 등)을 조합하여 해결할 수 있다. 이는 나중에 배울 테이블이라는 툴을 통해 가능하다. 
  - 패 시스템과 같이 완전히 새로운 시스템도 기존 시스템과 동일한 메커니즘이라면 별도로 만들 필요가 없다. 
  - 펫 합성 시스템이 없더라도 캐릭터 합성 시스템이 있다면, 펫 합성 관련 시스템은 새로 만들 필요가 없다. 

### 1.4. 기능 단위 분해를 위한 도구와 방법
기능 단위로 시스템을 분해하는 것이 어렵다면 **마인드맵**을 활용하는 것이 도움이 된다. 


- **인벤토리 시스템 예시**:
  - **주요 기능**:
  - 획득한 아이템 저장 기능 
  - 저장한 아이템 보여주기 기능 
  - 기본적인 정렬 규칙 
  - 저장한 아이템 사용 기능 
  - 아이템 장착 기능 
  - 아이템 분해 기능 
  - **장착 기능 세부**:
  - 장착 
  - 교체 
  - 아이템 비교 기능 
  - **보조 기능**:
  - 가방 확장 
  - 검색 필터 
  - 프리셋 기능 
- **구현을 위한 시스템 목록 작성**: 위에서 나열한 기능들을 구현이 필요한 시스템 목록 형태로 작성한다. 
  - **중요도 표기**: 실무에서는 시스템 내에서의 중요도도 함께 작성하는 것이 좋다. 
  - 시스템이 돌아가지 않을 경우 필수적인 기능은 중요도가 높다. 
  - 없어도 시스템은 돌아가지만 불완전하거나 불편한 기능은 중요도가 낮다. 
- **직접적인 연관 없는 시스템 명시**: 인벤토리에서 아이템 강화, 합성, 거래소 판매 기능으로 연결될 경우, 해당 시스템들은 인벤토리 시스템과 직접 연관이 없으므로 인벤토리 기획서에 작성할 필요는 없다. 단지 어떤 인터페이스를 통해 연결될지만 명시하면 된다. 

### 1.5. 시스템 기획의 영역: 분류와 재배치
타워 디펜스 모드와 같은 미니 게임 기획 시, 떠오르는 시스템 부분을 두서없이 나열한 후 분류하고 재배치하는 과정이 필요하다. 


- **두서없이 나열된 시스템 분류**:
  - 기획자가 세팅해야 하는 것 
  - 컴퓨터가 계산해야 하는 것 
  - 컴퓨터가 생산해야 하는 것 
  - 컴퓨터가 판단해야 하는 것 
  - 컴퓨터가 출력해야 하는 것 
  - 컴퓨터가 재생해야 하는 것 
  - 유저와 상호작용해야 하는 것 
- 시스템 기획의 영역: 위 분류는 **시스템 기획의 영역**에 해당한다. 
  - 기획자가 세팅해야 하는 것에 대한 규칙 설계는 테이블 설계 시간에 배운다. 
  - 컴퓨터가 계산, 생산, 판단하는 것에 대한 규칙 설계를 고려해야 한다. 
- **목적어 기준 재배치**: 나열된 내용을 목적어 기준으로 공통된 것끼리 재배치한다. 
  - 맵, 타워, 캐릭터, 대포, 자원, 기타 등으로 나눌 수 있다. 
- **타워 디펜스 모드 **시스템 기획서** 구성**:
  - 핵심 시스템 (승패 규칙 등)인 **코어 시스템**과 **타워 시스템**이 먼저 온다. 
  - 자원, 캐릭터, 대포 시스템은 순서에 큰 상관이 없다. 
  - 각 카테고리에는 규칙 작성 방법을 배우지 않았더라도 참고용으로 읽을 수 있는 내용이 포함된다. 

### 1.6. 시스템 기획의 또 다른 축: 속성 단위 분해
시스템을 **속성 단위**로 분해하는 방법도 중요하다. 


- **속성이란?**: 사물의 성질, 특징, 본질적인 성질로, 사물을 다른 사물들과 구별하는 데 사용되는 성질이다. 
  - 현실을 추상화하고 단순화한 것으로, 보일 수도 있고 숨겨져 있을 수도 있으며 계산으로 산출될 수도 있다. 
- **개체란?**: 현실 세계에 대해 사람이 생각하는 개념이나 정보의 단위이며, 하나 또는 그 이상의 속성으로 구성된다. 
  - 예시: 사람을 구분하게 하는 속성으로는 얼굴, 키(겉으로 보이는 속성), 이름, 나이, 혈액형(숨겨진 속성), 체지방률, 지능 지수, MBTI(산출되는 속성) 등이 있다. 
  - 이름이 같더라도 다른 속성들이 다르기 때문에 개별 존재로 구분된다. 
- **젤리 예시 (쿠키런)**:
  - 젤리들을 구분하게 하는 속성: 이름, 생김새, 크기, 자석 반응 여부, 먹었을 때 점수 변화 여부, 체력 변화 여부, 속도 변화 여부, 젤리 변화 여부 등. 
  - **유저/초보 기획자 시야**: 점수를 주는 작은 젤리, 점수를 많이 주는 곰젤리, 체력을 주는 포션 등. 
  - 시스템 기획자** 시야**:
  - 작은 젤리, 곰젤리, 핑크 곰젤리: **점수 변화 속성** (점수를 준다는 메커니즘 동일) 
  - 포션: **체력 변화 속성** (체력 회복) 
  - 부스터 젤리: **데미지 무시, 속도 변화, 장애물 파괴 속성** 
- **젤리 담당 시스템 기획자의 역할**:
  - 오브젝트(젤리)가 갖게 될 **속성을 기획**한다. 
  - 이 속성을 연결하는 툴인 테이블을 기획한다. 
- **팀 전체의 역할 분담**:
  - 콘텐츠 기획자: 젤리 컨셉, 외형 기획 및 어울리는 속성 연결. 
  - 레벨 기획자: 맵 컨셉 기획 및 젤리 오브젝트 배치. 
  - 밸런스 기획자: 젤리 오브젝트 별 속성 수치 밸런싱. 
- **시스템 기획 프로세스**:
  - 시스템 기획자: 속성 및 상세 작동 규칙 기획. 
  - 프로그래머: 속성 작동 규칙 구현 및 테이블 구현. 
  - 콘텐츠 기획자: 테이블 속성, 아티스트 리소스 조합하여 젤리 생성. 
  - 밸런스 기획자: 젤리 속성 상세 수치 부여. 
  - 레벨 기획자: 젤리 맵 배치. 

### 1.7. 시스템 기획 역량의 중요성

- **시스템 기획은 필수**: 시스템 기획을 할 줄 모르는 콘텐츠 기획자는 업계에서 필요로 하지 않는다. 퀄리티 있는 콘텐츠 생산을 위해 시스템 기획** 역량은 필수**이다. 
- **어렵지 않으니 믿고 따라오기**: 시스템 기획은 어렵지 않으니 믿고 잘 따라오면 된다. 
- **숙제**: 좋아하는 게임에서 간단한 시스템 하나를 골라, **기능 단위로 분해해서 나열**해 본다.
