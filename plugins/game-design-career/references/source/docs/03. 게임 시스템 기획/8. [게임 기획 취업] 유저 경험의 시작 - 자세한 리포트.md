게임 기획에서 유저 경험**(UX)의 시작**은 무엇인가요? UI 기획은 화면에 담을 요소 결정, 레이아웃 배치, 구성 요소 크기, 색상 사용을 포함하며, 플레이어가 필요한 정보를 효율적으로 얻고 게임에 몰입할 수 있도록 **정보의 중요도와 노출 시점을 고려**하는 것이 핵심입니다.
## 1. 유저 경험의 시작, UI 기획의 중요성 
게임 기획에서 유저 경험**(UX)**은 UI 기획에서 시작되며, 화면에 담을 요소 결정, 레이아웃 배치, 구성 요소 크기, 색상 사용 등을 통해 플레이어가 정보를 효율적으로 얻고 게임에 몰입하도록 돕는 것이 핵심이다.


### 1.1. 화면에 담을 요소 결정: 정보의 중요도와 노출 시점 
1. **정보 과부하 방지**: 플레이어에게 모든 게임 정보를 한 번에 제공하면 UI 구성 요소가 너무 많아져 필요한 정보를 찾는 데 시간과 노력이 더 많이 들게 된다. 
  1. 필요한 정보를 제때 찾지 못하면 불이익이 발생할 수 있으며, 예를 들어 체력이 낮다는 사실을 빠르게 알아차리지 못해 캐릭터가 죽을 수도 있다. 
2. **정보 노출 전략**: 특정 정보는 필요할 때만 노출하거나, 플레이어가 필요할 때 직접 찾아서 볼 수 있도록 숨기는 것이 좋다. 
  1. UI/UX 기획은 화면을 어떤 요소들로 구성할지, 배치 위치, 크기, 색상, 디자인 등을 결정하는 영역이다. 
3. **깔끔한 화면 구성**: 한 화면을 구성하는 요소는 가급적 7개를 넘지 않는 것이 시각적으로 깔끔하고 좋다. 
  1. **세븐나이츠 1의 사례**: 모바일 게임 초창기 세븐나이츠는 당시 작은 폰 화면에 너무 많은 구성 요소를 넣어 복잡하게 느껴졌고, 필요한 메뉴를 찾기 어렵게 만들었다. 
  1. 이는 유저 경험에 대한 연구가 부족했던 당시 모바일 게임들의 일반적인 문제였다. 
  2. **세븐나이츠 키우기의 개선 사례**: 세븐나이츠의 최신 시리즈인 세븐나이츠 키우기는 방치형 게임임에도 불구하고, 기본적인 인터페이스와 전투 인터페이스를 한 화면에 깔끔하고 단순하게 담아냈다. 
  1. 자주 사용하지 않는 '업적' 버튼 같은 메뉴는 햄버거 버튼 내부로 옮겨 숨겼다. 
  2. 메뉴와 팀 정보도 숨길 수 있게 하여 필요할 때만 노출시킨다. 
4. **몰입감을 높이는 UI 통합**: 게임 플레이에 필요한 정보를 게임 속에 자연스럽게 녹여내어 심플함과 몰입감을 동시에 제공하는 방법도 있다. 
  1. **데드스페이스의 사례**: 이 게임은 체력 상태를 수트 등에 달린 게이지 바를 통해, 남은 탄약은 총 위에 떠 있는 홀로그램을 통해 알려준다. 
  2. 인벤토리 역시 화면을 덮는 새로운 인터페이스 대신, 플레이어가 홀로그램으로 인벤토리를 보는 것처럼 꾸며 몰입감을 높였다. 
  3. 모든 게임이 이 방식을 따라야 하는 것은 아니지만, 인터페이스 처리의 한 가지 방법으로 알아두면 좋다. 
5. **정보의 순차적 개방**: 한 화면에 너무 많은 정보를 제공해야 할 경우, 구성 요소를 순차적으로 개방하여 플레이어가 기존 화면에 익숙해질 때쯤 새로운 요소를 노출하는 것이 효과적이다. 
  1. **미개방 영역 처리 방법**:
  1. **아예 노출하지 않는 방법**: 게임 초보 플레이어가 너무 많은 정보에 압도되지 않도록 미개방 영역을 화면에서 완전히 숨긴다. 
  2. **잠금 처리하여 노출하는 방법**: 게임 콘텐츠를 어느 정도 진행한 플레이어에게는 미개방 영역을 노출하되 잠금 처리하여, 새로운 업적이나 캐릭터에 대한 기대감을 갖게 한다. 


### 1.2. 레이아웃 배치: 시선 유도와 정보 강조 
1. **레이아웃의 정의와 중요성**: 레이아웃은 화면 안에 요소들을 어떤 구도로 배치할 것인지를 의미하며, 화면 디자인의 첫 단계이자 좋은 UI 디자인을 만드는 데 결정적인 역할을 한다. 
2. **잘 정돈된 레이아웃의 효과**:
  1. 플레이어의 시선을 편안하게 하고, 시선이 이동해야 할 순서를 유도한다. 
  2. 정보의 계층 구조를 인식시켜 중요한 요소를 강조할 수 있다. 
  3. 이를 통해 정보 전달 효과를 극대화할 수 있다. 
3. **정보 중요도에 따른 배치 원칙**:
  1. **가장 중요한 정보**: 플레이어의 시선을 고려하여 화면 중앙에 최대한 가깝게 배치하는 것이 좋다. 
  2. **두 번째로 중요한 위치**: 왼쪽 상단이다. 대부분의 언어가 왼쪽에서 오른쪽으로 쓰여지기 때문에 시선도 같은 방향으로 흐르는 것이 일반적이기 때문이다. 
  3. **일반적인 게임의 **헤드업 디스플레이** 배치 구도**:
  1. **화면 중앙**: 가장 잘 보이는 영역으로, 전투 중에는 게임플레이 화면, 캐릭터 조준선, 인터페이스를 보여주고, 메뉴 화면에서는 중요한 정보를 배치한다. 
  2. **중앙 화면의 위와 아래**: 화면 중앙의 초점을 유지하면서도 볼 수 있는 영역으로, 타이머, 탄약 수, 제목, 튜토리얼 진행률 등 중요한 정보를 표시한다. 
  3. **우측 상단**: 눈에 잘 띄는 영역으로 체력 바, 제목, 상위 레벨 메뉴를 배치한다. 
  1. 게임에 따라서는 이 정보들이 우측 하단에 배치되는 경우도 많다. 
  4. **나머지 영역 (좌측 상단, 우측, 좌측 하단 등)**: 게임플레이에 비교적 덜 중요한 정보들이 배치되는 편이다. 
4. **레이아웃 기획 시 고려사항**:
  1. **장르별 중요 정보**: 장르에 따라 어떤 정보가 중요한지 다르므로, 유사한 게임을 참고하여 레이아웃을 구성하는 것이 좋다. 
  2. **기기별 가려지는 영역**: 아이폰의 노치 영역처럼 기기에 따라 화면 일부가 가려질 수 있음을 고려해야 한다. 


### 1.3. 일관성과 확장성을 고려한 레이아웃 
1. **일관성 유지**: 성격이 유사한 항목은 공간적으로도 유사한 곳에 배치하여 일관성을 높이는 것이 중요하다. 
  1. 동일한 역할을 하는 인터페이스 요소는 모든 페이지나 화면에서 동일한 위치에 표시해야 하며, 표시 디자인이나 방법 역시 일정한 규칙을 따라야 한다. 
  2. **나쁜 사례**: 예시 사진에서 같은 게임임에도 불구하고 '나가기' 버튼의 위치와 디자인이 제각각인 것은 좋지 않은 케이스이다. 
2. **다양한 **해상도 대응** 및 확장성**: 레이아웃은 다양한 해상도에 대응할 수 있는 형태로 제작되어야 한다. 
  1. 향후 새로운 내용이나 기능이 추가될 것을 감안하여 여유 공간을 만들어 두는 것이 필요할 수 있다. 
3. 크로스 플랫폼** 고려**: 크로스 플랫폼 게임이라면 다른 기기에서 어떻게 보여지고 조작되어야 할지도 함께 고려해야 한다. 
  1. **콘솔 버전**: 게임패드로 원하는 항목까지 이동하는 것이 어렵지 않은 위치에 배열해야 한다. 
  2. **모바일 버전**: 손가락으로 가려지거나 잘못 누르는 일이 잘 없는 위치에 배열해야 한다. 
  3. **PC 버전**: 해상도 차이로 모바일에서는 안 보이는 부분까지 다 보인다든가 하는, 모바일 버전에 비해 눈에 띄게 유리해지는 부분이 없는지 체크가 필요하다. 
  4. **뱅드림과 원신의 사례**: 뱅드림은 스마트폰 화면이 점점 커질 것을 예측하지 못하고 디자인한 것으로 추정되는 반면, 원신은 어느 기기, 어느 해상도에서도 어색하지 않게 보이는 '열린 디자인'을 사용하고 있다. 


### 1.4. 구성 요소의 크기: 중요도 강조와 사용성 확보 
1. **크기를 통한 중요도 강조**: 각 구성 요소의 크기 차이를 이용하여 중요도가 높을수록 더 강조되도록 하는 것이 좋다. 
  1. **사례**: 플레이어가 가장 자주 방문해야 할 메뉴를 다른 메뉴들보다 압도적으로 크게 배치하여 중요도를 강조한다. 
  2. 그다음으로 중요한 메뉴는 진행 중인 이벤트, 팀 편성, 캐릭터 관리, 미션 기반 시설 등으로 판단되며, 환경 설정, 우편함, 재화 충전 같은 메뉴는 비교적 덜 중요하게 배치된다. 
2. **터치 실수 방지**: 상호작용이 필요한 버튼 같은 요소들은 터치 실수가 일어나지 않도록 일정 크기 이상을 유지하는 것이 좋다. 
3. **텍스트 영역 고려사항**:
  1. **외국어 버전**: 외국어 버전을 고려하여 한글을 기준으로 한 크기보다 좀 더 크게 만들어야 한다. 
  2. **다양한 해상도**: 다양한 해상도를 고려해 글씨 크기를 정해야 한다. 
  3. **가독성 확보**: 보험 약관처럼 자세히 읽히고 싶지 않은 문장이 아니라면, 너무 작은 글씨는 사용하지 않는 것이 좋다. 
4. **정보 과부하 시 처리**: 한 화면에 너무 많은 정보를 담아야 한다면, 비교적 덜 중요한 정보를 툴팁, 팝업, 다음 페이지 등으로 빼서 구성 요소들이 너무 작아지지 않도록 하는 것이 좋다. 


### 1.5. 구성 요소의 색상: 직관적인 정보 전달과 몰입감 유지 
1. **색상을 통한 정보 전달**: 색상을 통해 플레이어에게 현재 상태를 직관적으로 알려주거나, 어떤 정보가 더 중요한 정보인지 인식하도록 할 수 있다. 
2. **색상 사용의 원칙**:
  1. **색상 수 제한**: 한 화면에 너무 많은 색깔을 사용하지 않는 것이 중요하다. 
  1. 단순한 배색이 시각적 요소를 명확하게 구별하는 데 도움이 된다. 
  2. 게임은 캐릭터, 아이템, 아이콘 등 화려한 색상을 많이 사용하므로, 유저 인터페이스 색상만큼은 최대한 심플하게 적은 종류를 사용하는 것이 좋다. 
  3. UI를 구성하는 색상 중 서로 다른 계열의 색상이 5종 이상 넘어가지 않도록 한다. 
  2. **모양과 패턴 활용**: 시각적인 구분이 필요하다면 색보다는 모양과 패턴의 변형을 주는 것을 고려하는 것이 좋다. 
  3. **핵심 강조**: 핵심적으로 강조해야 하는 부분이 있을 때만 다른 색을 사용하여 '필살기'처럼 활용해야 한다. 
  1. 너무 난잡하게 색을 사용하면 어떤 것도 강조되지 않는다. 
  4. **명확한 대비**: 배경색과 구성 요소의 색이 너무 비슷하거나, 활성화/비활성화 요소, 기능적으로 반대되는 요소의 색을 비슷하게 만들면 구분이 어려워 사용하기 힘들다. 
  1. 가급적 명확하게 대비되는 색을 사용하는 것이 좋다. 
3. **게임의 정체성과 **색상 맥락** 고려**:
  1. **게임 팔레트 활용**: UI 기획 시 게임의 정체성처럼 사용하고 있는 팔레트 색상을 활용하는 것이 좋다. 
  2. **일반적인 색상 위계 준수**: 일반적인 게임에서 자주 사용하는 색상의 위계를 가급적 어기지 않는 것이 좋다. 
  1. 예를 들어, 초록색 등급을 파란색 등급보다 높게 설정하면 플레이어들이 혼란스러워할 수 있다. 
  2. 상성 역시 "빨강은 초록 또는 노랑을 이긴다", "초록 또는 노랑은 파랑을 이긴다"와 같은 일반적인 색상 상성을 뒤집지 않는 것이 좋다. 
  3. **문화권별 색상 컨텍스트**: 색상의 컨텍스트는 문화권마다 다를 수 있으므로, 주요 타겟 문화권을 고려해야 한다. 
  1. **미국의 사례**: 주식이 올랐을 때 초록색, 내렸을 때 빨간색을 사용한다. 초록색은 안전, 빨간색은 위험을 상징하기 때문이다. 
  1. 미국에서 만든 스타워즈 게임 역시 버프를 초록색, 디버프를 빨간색으로 사용한다. 
  2. **한국과 일본의 사례**: 주식이 올랐을 때 빨간색, 내렸을 때 파란색을 사용한다. 빨간색은 활기, 파란색은 질병이나 우울함을 상징하기 때문으로 보인다. 
  1. 일본에서 만든 '프린세스 커넥트! Re:Dive'는 버프를 빨간색, 디버프를 파란색으로 사용한다. 


## 2. UI 기획 능력 향상을 위한 습관 
1. **기존 게임 UI 분석 습관**: UI 기획 시 기존 게임의 유저 인터페이스를 전체적으로 살펴보고, 구성 요소를 하나하나 뜯어보며 기획 의도를 추측해 보는 습관을 들이면 도움이 많이 된다. 
  1. **분석 예시**:
  1. 화면 중앙에 조작이 필요한 요소를 넣지 않고, 선택이 필요한 메뉴는 왼쪽에, 스크롤을 통해 정보 확인이 필요한 항목은 오른쪽에 배치한다. 
  2. 잘 사용하지 않지만 조작이 필요한 검색 기능은 우측 상단에 두어 잘못 눌러 키보드가 튀어나오는 불편함을 줄인다. 
  3. 과도한 스크롤로 인한 조작 불편함을 줄이기 위해 접기/펼치기 형태의 패널 인터페이스를 사용한다. 
  4. 스크롤이 되는 영역은 의도적으로 내용이 잘리게 배치하여 아래에 내용이 더 있다는 시각적인 힌트를 제공한다. 
  5. 메뉴의 종류가 늘어날 가능성에 따라 개별 탭 메뉴나 드롭다운 메뉴를 사용한다.
