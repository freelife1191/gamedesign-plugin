게임 기획자가 퀘스트를 구성할 때 가장 중요하게 고려해야 할 것은 무엇일까요? 퀘스트의 시작 조건, 달성 조건, 보상 등 세부적인 요소들을 함수처럼 정의하고, 각 조건에 대한 기획 의도를 명확히 설정해야 합니다. 특히, 플레이어의 기존 플레이 이력을 어떻게 반영할지, 다른 퀘스트나 시스템과의 충돌은 어떻게 방지할지에 대한 깊이 있는 고민이 필요합니다.
## 1. 게임 퀘스트 구성 요소와 기획 방법론
게임 기획자가 퀘스트를 만들 때 고려해야 할 다양한 구성 요소와 함수적 접근 방식을 상세히 설명한다.


### 1.1. 퀘스트 구성 요소 분석의 중요성
1. **퀘스트 시스템 분석의 필요성**: 새로운 퀘스트를 만들 때는 해당 게임의 **퀘스트 시스템 구성 요소**를 먼저 분석해야 한다.
  - 이는 게임 기획 지망생이 포트폴리오 작성 시 기획 역량 부족을 드러내지 않기 위해 필수적이다.
  - 만약 퀘스트의 **완료 NPC**를 작성하지 않으면, 유저 시야를 넘어서지 못한 기획자로 보일 수 있다. 

2. **인터페이스에 보이지 않는 **퀘스트 구성 요소: 게임의 퀘스트 인터페이스 화면에서는 보이지 않는 구성 요소도 존재한다.
  - 예시로는 **퀘스트가 플레이어에게 노출되는 조건**이나 **퀘스트 완료 시점에 변화되는 것** 등이 있다. 
  - 겉으로 퀘스트처럼 보이지 않지만 실제로는 퀘스트의 일종인 경우도 흔하며, 이는 퀘스트 기획에 포함된다. 
  - 예시: **업적, 시즌 패스, 미션, 가이드라인, 튜토리얼, 월드 이벤트** 등. 


### 1.2. 퀘스트 콘텐츠 데이터 입력 항목
게임 콘텐츠 기획자가 퀘스트를 만들 때 입력해야 하는 데이터는 다음과 같다.

1. **업적(Achievement) 예시 데이터**:
  - **카테고리**: "업적" 
  - **대분류**: "전투" 
  - **소분류**: "전리품 업적" 
  - **소분류 화면 내 정렬 순서**: 1번 
  - **제목**: "1천억이 높다 하대 하늘 아래 매수로" 
  - **설명**: "사냥으로 누적 1천억 매소 획득" 
  - 달성 카운트 조건: "아이템 획득" 
  - 달성 카운트** 조건 채우는 방법**: "사냥" 
  - **재화**: "이전 ES 매소" 
  - **달성 횟수**: 1천억 
  - 보상: "업적 포인트 100" 

2. **퀘스트 설명과 달성 조건의 구분**:
  - 퀘스트 설명은 마법의 주문이 아니므로, 설명을 쓴 것만으로 의도대로 달성 현황이 카운트될 것이라 생각하면 안 된다. 
  - 의도한 달성 조건을 **주어, 동사, 목적어**로 분해하여 명확히 해야 한다. 

3. **콘텐츠 기획자가 입력하지 않는 데이터**:
  - **달성 날짜, 진행 상황, 완료 여부** 등은 콘텐츠 기획자가 입력하지 않는다. 
  - 이는 퀘스트 시스템 기획 단계에서 플레이어의 활동 이력을 시스템에 반영하고 인터페이스로 보여주도록 기획하고 구현하는 부분이다. 
  - 유저에게 보인다는 이유로 퀘스트 테이블에 달성 날짜, 진행 상황 등을 입력하는 것은 이상한 테이블 기획이다. 


### 1.3. 시즌 패스 미션 예시 데이터
1. **시즌 패스 미션 데이터**:
  - **카테고리**: "시즌 패스 미션" 
  - **시즌**: 1 
  - **분류**: "1일 미션" 
  - 리셋 주기: 1일 단위 
  - 주의: '1일 미션' 분류가 자동으로 1일 단위 리셋을 의미하는 것은 아니며, UI 탭 분류 기준일 뿐이다. 리셋 주기는 별도 세팅이 필요하다. 
  - **제목**: "아라드 패스 메일 비밀창고 습격" 
  - **설명**: "황금 고블린의 비밀창고 앤 해 플레이" 
  - **인터페이스 아이콘**: 고블린 모양 아이콘 
  - 달성 카운트 조건: "플레이 완료" 
  - **목표물 대상**: 던전일 경우 "황금 고블린의 비밀창고" 
  - 달성 횟수: 'n' 
  - 바로가기** 목표물**: "황금 고블린의 비밀창고 입구" 
  - 이동 버튼을 통한 바로가기 기능 지원 시, 목표물과 별개로 세팅해야 한다. 
  - 예시: '장비 분해하기' 퀘스트는 목표물(장비 분해)과 이동 목적지(대장장이 NPC)가 다를 수 있다. 
  - 보상: "시즌 포인트 25개", "골드 5,000" 


### 1.4. 복잡한 퀘스트 분해 및 기획 고려 사항
1. **납품 퀘스트 예시 데이터**:
  - **카테고리**: "자유 퀘스트" 
  - **분류**: "납품 퀘스트" 
  - **제목**: "나느냐 숲의 운반자" 
  - **설명**: "비룡의 깃털 2개 납품" 
  - 퀘스트 인터페이스** 아이콘**: 알 모양 아이콘 
  - **의뢰인 NPC**: 주방장 캐릭터 
  - **NPC 대사**: "사냥감을 보면 피가 끌어서 그걸 나르는 건 성미에 안 맞아. 하지만 모두의 희망이라면 할 수 없지. 그거 운반 대행 부탁해." 
  - 달성 카운트 조건: 관리소의 목표물 제출 
  - **목표물**: "비룡의 알" 
  - **제출 개수**: 2개 
  - 보상: 3,600원, 경험치 180 
  - 해금** 보상**: 첫 클리어 보상으로 식당 식재료 해금 
  - 해금되는 식재료: '비룡의 알' 두 개 

2. **퀘스트 참가 및 진행 조건**:
  - 참가 조건: 헌터 레벨 4 
  - **월드 변화**: 퀘스트 수락 시 평소의 고대수의 숲이 퀘스트 수행 가능한 평행 우주의 고대수의 숲으로 변화한다. 
  - **제한 시간**: 50분 
  - 실패 조건:
  - 3,000초 안에 클리어 못 했을 때 
  - 플레이어 넉다운이 3회 이상 발생했을 때 

3. **퀘스트와 오브젝트 상호작용 변화**:
  - **퀘스트 없을 때**: 고대수의 숲 맵에 비룡 알이 있지만 내비게이션 기능 미지원, 납품해도 카운트 증가 없음 (장식품 같음). 
  - **퀘스트 있을 때**:
  - 비룡알 위치 추적 기능 제공. 
  - 비룡알을 주어 납품 박스에 납품하면 퀘스트 달성 조건 카운트. 
  - 두 개 납품 시 퀘스트 완료. 

4. **퀘스트 기획 시 고려해야 할 **예외 처리:
  - 퀘스트를 받았을 때 **변화되는 것**은 무엇인가? 
  - 퀘스트와 연관된 **오브젝트**는 무엇이며, 어디에 있어야 하는가? 
  - 오브젝트는 **언제 어떤 상태로 활성화**되는가? 
  - 무슨 **상호작용**이 가능한가? 
  - 어떤 기준으로 **실패**하고, 오브젝트가 **리젠**되는가? 
  - 엔진에서 레벨 파일을 열어 오브젝트를 의도한 위치에 배치하는 작업까지 해야 한다. 
  - 이 모든 것을 할 수 있어야 진정한 퀘스트 기획자이다. 


### 1.5. 퀘스트 기획 시 작성해야 할 상세 항목
1. 시작 가능 조건:
  - 이전 퀘스트 클리어, 특정 레벨 달성, 특정 지역 방문, 특정 오브젝트 상호작용 등. 
  - 시작 조건이 되었을 때, 퀘스트가 **언제, 어떻게, 어디서 노출**되어야 하는가? 
  - 달성 조건** **카운트** 시작 시점**과 **퀘스트 노출 시점**이 일치하는가? (예: 노출 전 수행 횟수 인정 여부) 
  - 시작 가능 조건을 만족 시 퀘스트가 **자동 시작**되는가, 아니면 **상호작용이 필요한가**? 
  - 시작 조건이 **한 개인지 여러 개인지** 결정해야 한다. 
  - 시작 전 **대사나 연출**, **퀘스트 수락 방법**, **시작 시 발생하는 일** (예: 특정 월드 탈바꿈, 몬스터 퀘스트 아이템 드랍 시작) 등을 기획한다. 

2. **진행도 계승 및 **충돌 방지:
  - **기존 퀘스트 진행도 계승 여부**: '1억 매소 모으기' 완료 후 '10억 매소 모으기' 등장 시, 1억은 채워진 상태로 시작할지 결정한다. 
  - **다른 퀘스트 또는 시스템과의 충돌 여부**: 충돌 방지를 위한 처리를 고민해야 한다. (원신 예시 예정) 

3. **퀘스트 진행 중 발생하는 일**:
  - 특정 몬스터 출현, 호위, NPC 이동, 상호작용 용도 오브젝트 리젠 등. 

4. 달성 조건** 및 결과 분기**:
  - **달성 조건이 여러 개인지**: 각 조건의 달성 카운트 방식, 예외 케이스 등을 고려한다. 
  - **결과에 분기가 있는지**: 있다면 어떤 기준이며, 각각 어떤 결과로 분기되는지 결정한다. 
  - 실패 조건: 실패 시 어떻게 되는지, 자동 취소 또는 재시작, 중간 자동 세이브 기준 등을 설정한다. 
  - **퀘스트 종료 조건**: 달성 조건 완료, 제한 시간 초과 등. 

5. **달성 조건 완료 시 발생하는 일**:
  - NPC에게 말 걸면 보상 지급, 세이브 포인트 지정, 상호작용 가능했던 오브젝트 비활성화, 퀘스트 아이템 드랍 중단 등. 
  - 달성 카운트 중지 여부, 연계 퀘스트에 계승될 수 있도록 계속 카운트할지 등 예외 처리도 필요하다. 

6. **퀘스트 종료 방법 및 결과**:
  - **종료 방법**: 특정 NPC와 대화, 자동으로 보상 화면 출력 등. 
  - **종료 시 발생하는 일**: 보상 지급, 플레이어에게 일어나는 변화 (다음 맵 이동, 다음 스텝 진행 가능, 월드 지형 변화 등). 
  - **보상**: 보상 종류와 지급 방식. 

7. **퀘스트의 재미**:
  - 만든 퀘스트가 재미있는지도 신경 써야 한다. 


### 1.6. 함수적 접근: 퀘스트 생성 함수
1. **함수의 개념**:
  - 물약 1개 100원일 때, 3개는 300원, x개는 100x원이다. 이를 함수 f(x) = 100x로 표현할 수 있다. 
  - 퀘스트 생성 함수 f(x, y)에서 x는 아이템, y는 획득하면 성공한다는 것이 구현되어 있다고 가정한다. 
  - 콘텐츠 기획자가 X(메소), Y(1천억)을 넣으면 "메소 1,000억 개 획득 퀘스트"가 만들어진다. 

2. 함수** 기획 및 활용**:
  - 기획자는 f(x, y)가 무엇인지, 무엇을 넣을 수 있게 할지, 넣은 값을 어떤 규칙으로 처리할지를 기획한다. 
  - 콘텐츠 기획자는 X, Y의 어떤 값을 넣어야 재미있을지를 기획한다. 
  - 만약 필요한 함수가 없다면, 새로운 함수의 작동 규칙을 직접 기획하고 개발해야 한다. 
  - X, Y 외에 Z까지 함수에 넣고 싶다면 f(x, y, z) 함수를 기획하면 된다. 
  - 실제 개발 용어도 함수라고 하며, 수학의 함수 개념과 동일한 구조로 개발된다. 

3. **함수 이해의 중요성**:
  - 함수의 개념을 이해해야 기존 함수에 X, Y 값을 넣어 퀘스트를 만들 수 있다. 
  - 신입 기획자가 퀘스트 기획서에 만들고자 하는 퀘스트를 실제 구현 가능한 형태로 X, Y 등으로 분해하여 작성하면 실무 이해도가 높다고 판단되어 합격 가능성이 높아진다. 


### 1.7. 퀘스트 시작 조건 함수
1. **시작 조건 함수의 종류**:
  - 레벨 달성, 퀘스트 완료, NPC와의 상호작용, 특정 사물(비밀의 문 등)과의 상호작용, 특정 아이템 획득 또는 사용, 특정 위치나 지역 도달, 게임 속 시간(낮밤, 특정 시간), 현실 기준 특정 날짜나 요일 등. 

2. 시작 조건** 기획 시 고려 사항**:
  - 기획 의도: 왜 특정 시작 조건을 설정했는가? (예: 50레벨 미만 유저를 문전 박대하기 위해 50레벨 달성 조건 설정) 
  - **조건 개수**: 시작 조건이 한 개인가, 여러 개인가? (예: 챕터 1 '영웅의 탄생' 퀘스트 완료 및 50레벨 달성) 
  - **시작 시점과 노출 시점 일치 여부**: 뒤에서 예시로 설명 예정. 


### 1.8. 퀘스트 달성 조건 함수
1. 달성 조건** 함수의 종류**:
  - **전투 관련**: NPC와 말 걸기, 몬스터 처치/공격, 시간 생존, 몬스터 X 공격 Y 회피, 스킬 사용 등. 
  - **아이템/오브젝트 관련**: 아이템/오브젝트 획득, 사용, 보유, 장착, 상호작용 등. 
  - **월드 관련**: 특정 위치에 도달하기 등. 
  - **콘텐츠 관련**: 콘텐츠 플레이/클리어, 레벨 달성, 특정 카테고리 퀘스트 y개 달성 등. 

2. **달성 조건 기획 시 고려 사항**:
  - 기획 의도: 달성 조건의 기획 의도는 무엇인가? 
  - **조건 개수**: 달성 조건이 하나인가, 여러 개인가? 
  - **인정하지 않는 케이스**: 달성 조건으로 인정하지 않는 케이스가 있는가? 
  - 이력** 인정 여부**: 기존에 달성했던 이력을 인정해 주는가? 
  - 실패 처리** 조건**: 달성 실패로 처리되는 조건이 있는가? 있다면 어떻게 되는가? 

3. **이력 인정 관련 복잡성 (원신 사례)**:
  - **싱글 게임**: 몬스터헌터 월드처럼 같은 맵에 입장하더라도 퀘스트에 따라 평행 세계 맵으로 들어가면 별 문제가 없다. 
  - **오픈월드 게임**:
  - 퀘스트 A를 받으면 퀘스트 B를 비활성화시키는 처리가 필요하다. 
  - MMORPG는 이보다 더 복잡하며, 맵 자체를 조각내 평행 우주로 만들어야 할 때도 있다 (와우 비상 변화 시스템). 
  - **이력 인정 여부 결정**:
  - **캐릭터 특성 만렙 달성 미션**: 7챕터 이전에 달성한 이력을 인정해 준다. (신캐 출시까지 기다려야 하는 상황 방지) 
  - **임의 비경 던전 클리어 미션**: 7챕터 이전에 했던 것은 인정해주지 않는다. (제작한 무기를 여전히 갖고 있어야 하는지 등 복잡성 회피) 
  - **사례 무기 두 개 제작 미션**: 7챕터 이전에 했던 것은 인정해주지 않는다. 
  - **기획 의도 명확화**: 어떤 게임의 신규 퀘스트 기획 시, 이러한 상황에 어떻게 처리하고 싶은지 기획 의도에 따라 결정하고 기획서에 명시해야 한다. 
  - **기획 미스**: 기획 의도, 유저 편의성, 기존 구현 상태 등을 고려하지 않으면 프로그래머가 버그가 아닌 기획 미스로 처리할 수 있다. 
  - **데이터 저장 문제**: 플레이어 로그에 특정 조건 달성 횟수를 저장하지 않았다면, 해당 퀘스트는 기획 파기해야 할 수도 있다. 
  - **구현 불가능한 **함수: 서버 프로그래머가 구현 불가능하다고 말하는 퀘스트 함수는 누적된 로그가 없어 기존 이력 소급이 어려워서일 가능성이 높다.
