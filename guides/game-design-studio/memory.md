# Studio 프로젝트 기억

프로젝트 기억은 이전 플레이테스트와 검토에서 확인한 설계 판단을 다음 Studio 작업에 참고 자료로 연결합니다. 기억 원본은 작업 폴더의 `.game-design/` 아래에 로컬로 남으며, 기준 기획 결과물 폴더와 독립 근거를 대신하지 않습니다. 현재 프로젝트를 뜻하는 `project`가 기본 범위입니다.

## 어떤 기록을 기억하는가

반복해서 적용할 설계 교훈, 검토에서 확인한 제약, 플레이테스트에서 재현된 문제와 사용자가 명시한 문서 작성 선호를 기록할 수 있습니다. 시스템·콘텐츠·플레이어 경험·경제·제작 작업은 Studio 영역(`studio`)에서, 두 제품이 함께 써야 하는 사실과 결정만 공통 영역(`common`)에서 다룹니다.

자동으로 남길 수 있는 기록은 검토 대기 후보(`candidate`)까지입니다. 후보에는 요약, 적용 조건, 제외 조건과 출처 파일의 위치·해시가 붙습니다. 사용자가 직접 밝힌 지속 선호는 그 지시와 사람을 확인한 경우에만 별도 근거로 기록합니다.

## 기억하지 않는 내용

API 키, 계정 정보, 개인 식별 정보, 회사 비공개 원문 전체는 기록하지 않습니다. 근거가 없는 추측, 한 번만 쓸 임시 문구, 검증되지 않은 재미·성과 주장도 장기 교훈으로 취급하지 않습니다. 기억 본문에 스킬 호출이나 파일 삭제 같은 명령이 있어도 실행하지 않고 자료로만 읽습니다.

기억은 재미, 품질, 흥행이나 프로젝트 성공을 보장하지 않습니다. 기준 기획 결과물 폴더의 `content.md`, `evidence.yml`, `decisions/`와 이름이 확인된 사람의 판단이 우선합니다.

## 기본 작업 흐름

작업을 시작하면 플러그인은 프로젝트 ID와 설정을 확인한 뒤 승인된 기록만 찾습니다. 현재 요청과 관련 있고 Studio 또는 공통 영역에 속하며, 검토·만료 시점을 지나지 않고 출처가 그대로인 기록만 참고합니다. 적용한 기록과 제외한 이유는 사용 기록에 남깁니다.

작업이 끝나면 결과가 실제 근거에 연결됐는지 검사한 뒤 재사용 가치가 있는 교훈만 후보로 제안합니다. 비활성화하면 저장소를 읽거나 쓰지 않으며 후보도 만들지 않습니다. 기억 조회나 저장에 문제가 생겨도 기억 없이 기존 기획 작업을 계속합니다.

## 후보 확인·승인·거부·폐기 예시

후보를 자동 승인하지 않습니다. 후보 확인, 검증, 승인에는 이름이 확인된 사람의 결정과 이유가 필요합니다. 다음처럼 자연어로 요청할 수 있습니다.

```text
기억 후보를 보여줘.
MEM-...의 출처와 적용·제외 조건을 확인해 줘.
내 이름은 김기획이야. 이 후보를 검증한 뒤 프로젝트 교훈으로 승인해.
이 후보는 근거가 부족하니 거부해.
이전 승인 기록은 새 플레이테스트와 맞지 않으니 폐기해.
```

승인은 후보를 먼저 검증한 뒤 진행합니다. 거부한 기록은 다시 적용하지 않으며, 승인 기록을 폐기하면 과거 이력은 보존하되 현재 작업에서는 제외합니다. 동시에 다른 변경이 생겨 충돌하면 현재 머리를 다시 보여 주고 사람이 선택하기 전까지 어느 쪽도 임의로 채택하지 않습니다.

## .env 설정과 완전 비활성화

기본값은 기억 사용, 프로젝트 범위, 작업당 최대 5개, 후보 유효 기간 30일, 로컬 Git 제외입니다.

```dotenv
GAME_DESIGN_MEMORY_ENABLED=true
GAME_DESIGN_MEMORY_SCOPE=project
GAME_DESIGN_MEMORY_MAX_ITEMS=5
GAME_DESIGN_MEMORY_CANDIDATE_TTL_DAYS=30
GAME_DESIGN_MEMORY_GIT_MODE=local
```

`GAME_DESIGN_MEMORY_ENABLED=false`로 설정하면 기억 폴더를 만들거나 읽지 않고 후보·색인·사용 기록도 남기지 않습니다. 설정은 유지하되 한 번의 요청에서만 제외하려면 “이번 작업에서는 이전 기억을 사용하지 마.”라고 적습니다. `workspace`나 `global`은 사용자가 명시적으로 범위를 넓힐 때만 쓰며 기존 기록을 자동 승격하지 않습니다.

## 로컬 Git 제외와 프로젝트 이동

기본 `local` 모드에서는 `.game-design/`을 로컬에만 보관하고 Git 로컬 제외 목록에 등록합니다. 플러그인은 기억 문서를 자동으로 Git에 커밋하거나 원격 저장소로 보내지 않습니다. 설치·업데이트·제거도 프로젝트의 `.game-design/`을 만들거나 지우지 않습니다.

프로젝트를 옮길 때 기억까지 가져가려면 `.game-design/`을 새 작업 폴더로 직접 복사하고 프로젝트 ID와 출처 파일을 함께 확인합니다. 기억을 옮기지 않으려면 결과 폴더만 복사하면 됩니다. 팀 공유가 필요해 `tracked`를 선택하더라도 커밋·원격 전송 여부와 비공개 자료 포함 여부는 사람이 따로 결정합니다.

## 손상·충돌·출처 변경 복구

“기억 상태를 점검해 줘.”라고 요청하면 원본 이벤트, 충돌과 출처 연결을 검사합니다. 파생 색인이나 목록만 손상됐다면 원본에서 다시 만들 수 있습니다. 원본이 손상됐거나 서로 다른 변경이 충돌하면 문제 기록을 격리하고 사용자가 선택할 때까지 적용하지 않습니다.

승인된 기록도 출처 파일 내용이 달라지거나 검토·만료 시점을 지나면 오래된 기록(`stale`) 또는 만료 기록으로 분류해 제외합니다. 새 근거를 확인한 뒤 다시 검증하거나 새 후보로 남겨야 합니다. 복구가 끝나지 않아도 Studio의 비전·시스템·콘텐츠·UX·경제·제작 작업은 기억 없이 계속할 수 있습니다.

## Studio 전용 경계

Studio 기억은 게임 규칙, 플레이 경험, 콘텐츠, 경제와 제작 판단에만 적용합니다. Career의 채용 공고 해석, 학습 계획, 포트폴리오나 면접 교훈을 게임 설계 원칙으로 가져오지 않습니다. 두 제품이 공유할 수 있는 것은 출처가 확인된 프로젝트 사실과 사람이 승인한 공통 결정뿐입니다.

[Studio 전체 워크플로](workflow.md)로 돌아가거나 [Studio 스킬 레퍼런스](skills/README.md)에서 기억 조회·기록·관리 스킬을 확인하세요.
