# 컷씬 장면·이미지 사전 설계

이 가이드는 컷씬 개요, 장면 흐름, 개별 장면, 연속성 기준, 마스터 프롬프트와 이미지 검토를 하나의 패키지로 정리합니다. 이미지 생성은 기획과 별도 단계입니다. **비용을 확인하고 이름을 기록한 실시간 승인을 받기 전에는 이미지 제공자를 호출하지 않습니다.**

## 제공자와 품질을 먼저 고르기

이미지 안에 한글 문자가 없는 컷씬 프레임은 Codex의 호스트 `image_gen`으로 먼저 시도합니다. **API 키가 있어도 유료 생성 승인으로 보지 않습니다.** 호스트 결과가 만족스럽지 않거나 반복해서 실패하면 현재 결과를 보존한 뒤 `gpt-image-2`의 예상 비용과 품질을 안내합니다. 사용자가 승인한 뒤에만 새 비용 확인과 생성 단계로 넘어가며, 유료 이미지 제공자로 자동 전환하지 않습니다.

이미지 픽셀 안에 한글 문자가 반드시 들어가야 하면 `gpt-image-2`를 사용합니다. 자막이나 UI 문구를 후편집 레이어로 합성할 수 있다면 텍스트 없는 원본 프레임을 먼저 만드는 편이 비용과 수정에 유리합니다.

- `low`: 대부분의 컷씬 초안, 스토리보드와 변형 이미지에 쓰는 기본값
- `medium`: `style-master`, 선택된 마스터 키 이미지, 고화질 필요가 확인된 결과에만 사용
- `high`: 영상용 핵심 프레임이나 게임 원화처럼 세부 묘사가 반드시 필요한 예외에만 사용하며, 추가 비용과 이유를 별도로 승인

모든 이미지를 `high`로 올리는 권고는 하지 않습니다.

컷씬의 목적, 플레이어가 조작을 되돌려받을 때의 게임 상태, 장면 흐름과 개별 장면, 인물·배경·소품의 연속성 조건을 먼저 정합니다. 참고 이미지의 권리 상태, 원하는 모델·품질·크기, 유한한 USD 상한도 함께 준비합니다. 결과물은 `cutscene-brief`, `cutscene-shot-package`, `cutscene-prompt-package`, `cutscene-cost-estimate`, `cutscene-continuity-review`로 남깁니다. 기준 기획 결과물과 [이미지 자산 가이드](image-assets.md)의 권리·사람 검토 경계도 확인하세요.

## 세 가지 작업 모드

### 📝 프롬프트만 준비하기 (`Prompt Only`)

프롬프트만 준비하기 모드는 이미지 파일을 만들지 않습니다. 컷씬 개요, 장면 흐름표, 장면 목록, 연속성 기준, 스타일·참고 마스터 계획, 프롬프트 패키지와 예상 경로만 작성합니다. 이미지 제공자 호출은 0회이고 USD 비용도 0입니다. 참고 자료 해시, 승인 상태와 생성 기록을 임의로 만들지 않습니다.

```text
컷씬 brief와 beat만 작성
```

```text
shot list와 continuity bible 작성
```

```text
마스터 프롬프트 패키지만 작성
```

대사만 달라지는 변형은 새 이미지가 아니라 덧씌우는 텍스트 정보로 남깁니다. 새 핵심 장면이나 화면 구성이 필요한 시각 변형은 기존 자산을 덮어쓰지 않고 새 파생 ID를 부여합니다.

### 💰 비용만 확인하기 (`Estimate Only`)

비용만 확인하기 모드는 현재 단계의 비용을 계산하지만 이미지는 생성하지 않습니다. 다음 단계의 기획과 비용 초안은 미리 만들 수 있습니다. 유료 생성은 `style-master → reference-masters → keyframes → storyboard` 순서로만 진행합니다. 현재 단계마다 유효한 비용 계산과 이름을 기록한 실시간 승인이 필요합니다. `style-master` 뒤의 단계는 앞선 모든 단계가 완료되어야 하며, 선행 단계가 없는 `style-master`는 승인 직후 생성할 수 있습니다.

```text
스타일 마스터 비용과 승인
```

비용 계산에는 다음 내용을 빠짐없이 공개합니다.

- 자산 ID와 수량
- 이미지 제공자, 모델, 품질과 크기
- USD 최소·예상·최대 비용과 유한한 상한
- 재시도 여유분, 가격 출처, 가격 확인 시각과 `costStatus`
- 현재 비용 계산·가격 스냅샷·요청 일정에 연결된 승인 기록

호스트가 비용을 알려 주지 못하면 `costStatus`는 `unavailable`입니다. 이때 비용을 0으로 간주하지 않으며 이미지 제공자 호출은 0회로 멈춥니다. 상한이나 최대 비용이 없어도 생성할 수 없습니다.

### 🎬 승인 후 생성하기 (`Generate After Approval`)

승인 후 생성하기 모드는 현재 단계의 정확한 비용 계산을 공개한 뒤에만 쓸 수 있습니다. 승인에는 승인자 이름, 승인 시각, 대상 단계, 수량, 모델, 품질, 크기, USD 범위, 상한, 재시도 여유분, 가격 확인 시각과 `costStatus`가 묶여야 합니다. 이전 단계의 승인이나 포괄 승인은 다음 단계에 재사용할 수 없습니다.

```text
승인한 스타일 master 생성
```

`style-master`가 완료되고 승인 기록이 현재 상태와 일치하면 참고 이미지를 다시 연결합니다.

```text
reference master bound prompt 재계산
```

```text
reference master 비용과 승인
```

`reference-masters`가 완료되기 전에는 핵심 장면을 생성하지 않습니다. 현재 단계의 비용 계산, 이름이 기록된 승인 또는 필요한 선행 단계 완료가 없으면 이미지 제공자 호출 0회로 멈춥니다. 제공자를 호출한 뒤 실패했다면 성공한 파일과 승인 기록, 실패한 안정 자산 ID의 재시도 가능·종료 결과를 보존하고 추가 호출 없이 멈춥니다.

```text
keyframe 비용과 승인
```

`keyframes` 완료는 스토리보드의 생성 준비 연결과 유료 생성에만 필요합니다. 스토리보드 기획·검토·비용 초안은 먼저 만들 수 있습니다. 시각 변형도 새 파생 ID, 별도 비용 계산과 별도 실시간 승인을 거칩니다. 대사만 바뀌는 변형에는 새 이미지와 이미지 제공자 호출이 없습니다.

```text
storyboard와 variant 비용과 승인
```

생성에 성공했다는 이유만으로 `document-approved`나 `production-candidate`가 되지는 않습니다. 스타일, 참고 마스터, 핵심 장면과 스토리보드가 어떤 원본에서 이어졌는지와 실제 결과를 확인하는 연속성 검토를 먼저 마쳐야 합니다.

```text
continuity 검토와 실패 ID 재시도
```

재시도는 가장 최근에 재시도 가능 상태가 된 안정 자산 ID만 대상으로 합니다. 성공한 자산을 덮어쓰거나 종료된 실패를 다시 실행하지 않습니다. 일부 자산만을 위한 새 비용 계산을 만들지 않고, 아직 유효한 전체 단계의 비용 계산·가격 스냅샷·요청 일정과 남은 재시도 여유분을 사용합니다. 이전 승인이 오래됐다면 같은 비용 계산에 이름을 기록한 실시간 승인을 새로 받습니다. 비용 계산, 가격 또는 요청 일정이 달라졌거나 만료됐다면 현재 실행 환경은 새 기록 구간이나 재계획을 만들지 않으므로 이미지 제공자 호출 0회로 중단합니다.

## 🔄 작업 순서와 인계

1. `design-cutscene-visual-preproduction`으로 컷씬 패키지를 만듭니다.
2. `apply-document-quality-profile`에서 `cutscene-visual-preproduction` 구조 기준을 별도로 확인합니다.
3. 각 단계에서 **비용만 확인하기**로 비용을 공개하고 승인 대기 상태를 유지합니다.
4. 승인된 현재 단계만 생성한 뒤 완료 상태와 승인 기록을 보존합니다.
5. 변경 불가능한 자산 목록은 `validateCutsceneManifestHandoff({manifest})`를 통과한 뒤 `plan-image-assets`로 전달합니다.
6. 현재 단계에서 승인한 생성 요청은 `generate-image-assets`, 연속성 검토 항목은 `review-image-assets`로 전달합니다. 두 인계 모두 실시간 승인 권한을 대신하지 않습니다.
7. `review-cutscene-continuity.mjs`의 검토 기준을 통과한 뒤에만 사람이 문서·제작 후보 상태를 결정합니다.

컷씬 실무 경로는 [Studio 전체 워크플로](workflow.md), [스킬 레퍼런스](skills/README.md), [이미지 자산](image-assets.md), [Studio FAQ](faq.md)에서 다시 찾을 수 있습니다.
