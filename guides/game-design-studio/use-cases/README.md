# Game Design Studio 활용 사례

이 인덱스는 공통 역량을 익히는 사례, 콘셉트 제약을 비교하는 사례, 설치 스킬을 직접 쓰는 경로를 구분합니다. 사례 본문은 한 곳에만 두며, 여기서는 선택과 순서만 안내합니다.

## 역량·콘셉트·스킬 선택

| 진입점 | 선택할 때 | 먼저 확인할 결과 |
| --- | --- | --- |
| 역량 | 장르와 무관한 기획 원리와 검토 방법을 연습할 때 | [역량 사례 8개](competency-paths.md) |
| 콘셉트 | 같은 역량이 장르·플랫폼·운영 제약에서 어떻게 달라지는지 비교할 때 | [콘셉트 사례 10개](concept-scenarios.md) |
| 스킬 | 입력과 원하는 산출물이 분명해 한 작업만 직접 실행할 때 | [스킬 워크벤치](skill-workbench.md) |

범위가 아직 섞여 있으면 역량 사례에서 문제를 좁힌 뒤 전문 스킬로 이동합니다. 특정 장르의 관습, 회사 고유 양식이나 문체를 정답으로 복제하지 않습니다.

## 학습 경로

### 입문

`ST-C01 → ST-C02 → ST-C03` 순서로 플레이어 약속, 행동 루프, 규칙을 구분합니다. 각 사례의 10분 미니 실습만 수행하고 사람이 설명할 수 있는 가정과 질문을 남깁니다.

### 응용

현재 문제에 맞춰 `ST-C04`부터 `ST-C07` 중 하나를 선택하고 표준 실습과 검토 기록까지 완료합니다. 수치와 성공 가능성은 prototype 또는 telemetry로 검증할 가정으로 유지합니다.

### 포트폴리오

완성 문서보다 문제 정의, 대안, 선택 근거, 반례, 검토와 반복 개선을 공개 가능한 별도 증거로 정리합니다. Studio Artifact와 Career Artifact는 합치지 말고 [결과물 카탈로그](../../use-cases/output-catalog.md)의 handoff 경계를 따릅니다.

### 전체 프로젝트

`ST-C01 → 필요한 도메인 사례 → ST-C08`로 진행합니다. 오케스트레이터는 최소 route를 정하고, 전문 역할은 finding을 제출하며, 이름 있는 사람이 범위·권리·승인과 공개 여부를 결정합니다.

## 스킬 워크벤치

[스킬 워크벤치](skill-workbench.md)는 설치된 Studio 스킬 15개의 직접 호출 신호, 피할 때, 입력, 결과와 조건부 다음 handoff를 연결합니다. 실제 입력과 완료 계약은 [스킬 레퍼런스](../skills/README.md)에서 확인하세요.
