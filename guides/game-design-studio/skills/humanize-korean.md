# 기획 문장 자연스럽게 다듬기

<a id="직접-호출-활용-humanize-korean"></a>

## 목적과 최종 산출물

`humanize-korean`은 AI처럼 들리는 번역투나 기계적인 병렬 표현을 찾아, 뜻을 바꾸지 않고 읽기 쉬운 한국어 수정안을 만듭니다.

## 사용할 때

검토가 끝난 기획 초안의 표현을 다듬고 싶을 때 사용합니다. 긴 문서는 `polish-game-design-writing`을 우선합니다.

## 사용하지 않을 때

새 규칙, 수치, 근거, 승인 상태를 만들거나 사실을 검증하는 용도로 쓰지 않습니다.

## 필수 입력과 선택 입력

- 필수: 다듬을 한국어 원문, 원문 보관 위치
- 선택: 문서 장르와 보수적인 수정 강도

## Codex App 요청 예시

**복사 가능한 요청문**

```text
@Game Design Studio 아래 기획 문장의 뜻·수치·ID를 바꾸지 말고 자연스럽게 다듬어. 바뀐 표현과 보류할 문장을 따로 알려줘.
```

## Codex CLI 요청 예시

```text
$game-design-studio:humanize-korean <원문 경로>의 문체만 다듬고 수치·ID·승인 상태는 그대로 보존해.
```

## 내부 진행 흐름

보호할 수치·이름·ID·링크를 먼저 확인하고 문체 패턴만 고칩니다. 수정안과 변경 요약을 분리해 남기며, 원문 반영은 사람이 결정합니다.

## 생성 파일과 결과 구조

예상 결과는 수정안과 변경 요약이며 별도 작업 폴더에 남습니다. 원본 파일을 자동으로 덮어쓰지 않습니다.

## 관련 템플릿·품질 프로필·전문 역할

[게임 기획 문장 윤문](polish-game-design-writing.md)의 보호 receipt와 `game-design-writing-editor` 검토를 함께 사용하면 긴 문서의 경계를 지킬 수 있습니다.

## 이미지·도식화 조건

문장 윤문은 이미지나 도식을 만들지 않습니다. 필요한 경우 [도식화 안내](../visualization.md)를 별도로 사용합니다.

## 검토·승인 기준

사실·수치·날짜·고유명사·명령·승인 상태가 바뀌지 않았는지 사람이 확인합니다. 자연스러운 문장이라는 이유만으로 기획이 승인되지는 않습니다.

## 실패·fallback·재개 방법

보호 항목 변경 가능성이 보이면 수정안을 폐기하고 원문과 보류 이유를 남깁니다.

## 다음 작업 요청문

자리표시자 `<원문 경로>`와 `<수정안 경로>`은 실제 경로로 바꿉니다. [공통 규칙](../../README.md#용어)을 따릅니다.

```text
$game-design-studio:polish-game-design-writing source=<원문 경로> output=<수정안 경로> 보호 항목 receipt와 함께 검수해.
```
