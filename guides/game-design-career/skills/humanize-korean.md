# 경력 문장 자연스럽게 다듬기

## 목적과 최종 산출물

`humanize-korean`은 포트폴리오와 학습 기록의 AI 같은 문체를 뜻을 바꾸지 않고 자연스럽게 다듬는 수정안을 만듭니다.

## 사용할 때

사실·관찰·추론·제안을 구분한 뒤 문장 표현을 정리할 때 사용합니다. 긴 문서는 `polish-game-design-writing`으로 보호 항목을 먼저 잠급니다.

## 사용하지 않을 때

경력 사실, 면접 답변, 채용 결과를 꾸미거나 새 근거를 추가하는 용도로 쓰지 않습니다.

## 필수 입력과 선택 입력

- 필수: 한국어 원문, 사실과 숫자를 보존할 기준
- 선택: 문서 장르와 수정 강도

## Codex App 요청 예시

**복사 가능한 요청문**

```text
@Game Design Career 아래 포트폴리오 문장의 사실·수치·회사명·역할을 바꾸지 말고 자연스럽게 다듬어. 수정안과 보류 문장을 구분해.
```

## Codex CLI 요청 예시

```text
$game-design-career:humanize-korean <원문 경로>의 문체만 다듬고 경력 사실과 승인 상태는 보존해.
```

## 내부 진행 흐름

보호 항목을 확인하고 문체만 고칩니다. 원문과 수정안을 분리하고, 반영 여부는 멘토나 작성자가 결정합니다.

## 생성 파일과 결과 구조

예상 결과는 수정안·변경 요약·보류 이유이며 별도 작업 폴더에 남깁니다. 원본은 자동으로 바꾸지 않습니다.

## 관련 템플릿·품질 프로필·전문 역할

[게임 기획 문장 윤문](polish-game-design-writing.md)과 `game-design-writing-editor`가 보호 항목 검토에 도움을 줍니다.

## 이미지·도식화 조건

문장 윤문은 이미지나 도식을 생성하지 않습니다. [경력 도식 안내](../visualization.md)는 별도 작업입니다.

## 검토·승인 기준

사실·수치·날짜·고유명사·공개 범위가 그대로인지 사람이 확인합니다. 문체가 좋아졌다고 채용 적합성이 승인되지는 않습니다.

## 실패·fallback·재개 방법

사실 보존을 확인할 수 없으면 수정안을 폐기하고 멘토 피드백 지점을 남깁니다.

## 다음 작업 요청문

자리표시자 `<원문 경로>`와 `<수정안 경로>`은 실제 경로로 바꿉니다. [공통 규칙](../../README.md#용어)을 따릅니다.

```text
$game-design-career:polish-game-design-writing source=<원문 경로> output=<수정안 경로> 보호 항목 receipt와 함께 검수해.
```
