# Game Design Career 5분 빠른 시작

목표는 시스템 기획자를 준비하는 입문자의 현재 상태를 12주 학습·포트폴리오 증거 계획으로 바꾸는 것입니다. App 자연어 호출과 명시적 스킬 호출 중 하나만 사용하세요.

## 시작 전에 준비할 입력

- 목표 역할 또는 비교하고 싶은 역할 후보
- 현재 경력 단계, 가능한 주당 시간과 12주 제약
- 보유한 게임 분석, 기획 문서, 프로젝트와 피드백
- 지원 지역·플랫폼·장르 선호와 현재 채용공고(있다면)

이력서나 포트폴리오에 없는 경험과 성과를 만들지 마세요. 개인 연락처, 타인의 개인정보와 회사 비공개 자료는 제거한 뒤 공유합니다.

기본적으로 현재 프로젝트에서 사람이 승인한 Career 기억만 참고합니다. 이전 기록을 쓰지 않으려면 요청 끝에 “이번 작업에서는 이전 기억을 사용하지 마.”라고 적으세요. 자세한 범위와 후보 관리는 [Career 프로젝트 기억](memory.md)을 따릅니다.

역기획 근거를 구조화하려면 [Career 레퍼런스 분석](reference-analysis.md)을, 포트폴리오·면접의 한국어·영어 용어를 일관되게 유지하려면 [Career 용어 사전](glossary.md)을 사용합니다. 관찰에서 확인되지 않은 규칙과 승인되지 않은 용어 후보는 원문에 자동 반영하지 않습니다.

## App 자연어 호출

### 복사 가능한 요청문

```text
@Game Design Career 시스템 기획자를 목표로 하는 입문자의 현재 역량을 진단하고 12주 학습·포트폴리오 로드맵을 만들어줘.
```

### 진행 흐름

1. 플러그인이 목표 역할, 경력 단계, 보유 증거와 제약을 정규화합니다.
2. 자료가 부족하면 여러 임시 역할 경로와 확인 작업을 제시합니다.
3. 현재 역량과 필요한 역량을 증거 중심으로 비교합니다.
4. 12주 학습, 증거 프로젝트, 검토 시점과 포트폴리오 연결을 작성합니다.
5. 사용자는 목표 역할, 주당 시간, 공개 가능한 증거와 우선 프로젝트를 결정합니다.

### 예상 결과 요약

경로를 지정했다면 다음 구조의 Canonical Artifact를 예상할 수 있습니다. 경로를 지정하지 않았다면 쓰기 전에 제안 경로를 확인하세요.

```text
system-designer-12-week-roadmap/
├── content.md
├── evidence.yml
├── export-manifest.yml
├── decisions/
└── assets/
```

- `content.md`: 단계 진단, 역할 선택, 역량 격차, 12주 학습·증거 계획과 검토 기준
- `evidence.yml`: 채용공고와 역할 사실의 출처·날짜·한계
- `decisions/`: 선택한 역할, 포기한 대안, 시간 배분과 검토 owner
- `assets/`: 로드맵 도식 슬롯, prompt와 승인 상태
- 내보내기 manifest: 요청 형식별 준비·renderer·QA 상태를 기록하며 파일 생성이나 QA 통과를 미리 약속하지 않음

## 명시적 스킬 호출

부를 스킬이 정해지지 않았다면 `$game-design-career:game-design-career`로 시작합니다. 대표 진입 스킬이 요청이나 사례 ID를 소유 제품 하나와 실행 경로 하나로 좁히고 라우팅 영수증을 남긴 뒤 아래 스킬로 넘깁니다. 아래는 그 경로를 손으로 고정하는 요청문입니다.

### 복사 가능한 요청문

```text
$game-design-career:orchestrate-game-design-career 시스템 기획자 취업을 위한 역할 선택, 역량 격차와 12주 증거 계획을 만들어줘.
```

### 진행 흐름

오케스트레이터가 `entry`, `new-hire`, `junior-growth`, `transition` 또는 `unclear` 단계를 진단하고 필요한 최소 스킬 순서를 선택합니다. 현재 채용 사실이 필요하면 조사 단계를 먼저 두고, 포트폴리오·면접·성장 작업을 증거 ID로 연결합니다.

사용자는 다음 결정을 맡습니다.

- 시스템 기획자를 단일 목표로 확정할지 다른 역할과 비교할지
- 어떤 개인 자료를 근거로 사용하고 공개할 수 있는지
- 12주 동안 만들 증거 프로젝트와 주당 시간을 채택할지
- 채용공고의 최신성, 포트폴리오 권리와 최종 표현을 승인할지

### 예상 결과 요약

- `system-designer-12-week-roadmap/content.md`: 기준 로드맵
- `system-designer-12-week-roadmap/evidence.yml`: 역할·채용 근거와 공백
- `system-designer-12-week-roadmap/export-manifest.yml`: 요청 형식별 작업·renderer·QA 상태. 생성과 QA 성공은 실제 검증 뒤에만 기록
- `system-designer-12-week-roadmap/decisions/*.md`: 역할·범위·시간 결정
- `system-designer-12-week-roadmap/assets/`: 검증 전 로드맵 도식과 이미지 계획
- 차단 claim, 검증 작업, 다음 주 행동을 포함한 마지막 작업 보고

## 다음 요청

```text
방금 만든 로드맵에서 1주 차에 만들 가장 작은 증거를 정하고, 완료 기준과 검토 질문을 작성해줘.
```

반복해서 쓸 만한 교훈이 생겼다면 “기억 후보를 보여줘.”라고 요청한 뒤 출처와 적용·제외 조건을 확인하세요. 후보는 자동 승인되지 않습니다.
