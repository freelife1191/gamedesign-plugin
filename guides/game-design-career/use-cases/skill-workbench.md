# Career 스킬 워크벤치

이 표는 설치된 Career 스킬 25개를 작업 목적별로 나눠 보여 줍니다. 입력과 원하는 결과가 하나로 정해졌다면 해당 스킬을 직접 호출하세요. 여러 단계·역할·우선순위가 얽혔다면 오케스트레이터로 시작합니다. 생성·렌더링·추천 결과는 담당자의 승인이나 채용 결과를 대신하지 않습니다.

## 역할·근거

| 스킬 | 직접 호출할 때 | 근거와 담당자 확인 |
| --- | --- | --- |
| [`apply-document-quality-profile`](../skills/apply-document-quality-profile.md) | 한 결과물의 템플릿·품질 기준·확인 목록만 정할 때 | 선택 기록만으로 승인된 것은 아니며 `document-quality-editor`의 검토가 필요합니다. |
| [`humanize-korean`](../skills/humanize-korean.md) | 증거와 수치를 바꾸지 않고 문체만 다듬을 때 | 수정안은 `game-design-writing-editor` 또는 작성자가 의미·주장 경계를 확인합니다. |
| [`polish-game-design-writing`](../skills/polish-game-design-writing.md) | 긴 포트폴리오·학습 문장의 표현만 윤문할 때 | 경험·증거 ID와 공개·보류 판단은 사람이 다시 확인합니다. |
| [`map-game-design-career`](../skills/map-game-design-career.md) | 한 직무에 관한 현재 근거와 역량 차이만 비교할 때 | `career-strategist`가 사실·추론·제안을 구분합니다. |
| [`game-design-career`](../skills/game-design-career.md) | 어떤 스킬이 요청을 맡아야 할지 모를 때 | 실행 경로를 골랐다고 승인된 것은 아니며, 선택된 스킬의 승인 규칙이 그대로 적용됩니다. |
| [`orchestrate-game-design-career`](../skills/orchestrate-game-design-career.md) | 여러 경력 단계와 완료 조건을 하나의 요청 요약으로 묶을 때 | 실행 경로를 정해도 사실·추론·제안과 최종 결정 담당자는 그대로 구분합니다. |
| [`research-game-design-jobs`](../skills/research-game-design-jobs.md) | 한 직무·경력 수준·지역의 최근 채용공고 표본만 조사할 때 | 출처 URL, 위치, 확인일, 지역, 표본 범위와 재검토 시점이 없으면 현재 상황에 대한 주장을 만들지 않습니다. |
| [`analyze-game-design-references`](../reference-analysis.md) | 경쟁작 관찰을 포트폴리오 분석 근거로 정리할 때 | 관찰·추론·가설을 나누고, 설계 전환 제안은 `pending-review`로 남깁니다. |
| [`maintain-game-design-glossary`](../glossary.md) | 용어 후보와 스냅샷을 검토할 때 | 원문 자동 치환 없이 사람이 승인한 용어만 스냅샷에 넣습니다. |

직접 스킬은 입력과 원하는 결과가 하나로 정해졌을 때 사용합니다. 여러 단계와 우선순위가 남아 있다면 오케스트레이터가 실행 순서를 정한 뒤 알맞은 직접 스킬로 넘깁니다.

## 경계와 재개

직접 호출이 중단되면 해당 결과물의 `content.md → evidence.yml → decisions/ → export-manifest.yml`과 실패 기록을 보존합니다. 필요한 근거·권리·담당자 결정을 확보한 뒤 같은 실행 경로에서 이어 가세요. 여러 작업의 우선순위나 단계가 다시 얽혔을 때만 `$game-design-career:orchestrate-game-design-career`로 돌아갑니다.
