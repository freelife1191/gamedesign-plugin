# Game-design role-map method

Use this contract to compare evidence-building paths, not to predict a person's fixed suitability.

## Required role-path record

Every path contains these fields:

- `roleFamily`: a bounded family such as systems, content, economy, combat, level, narrative, UX, or live operations design.
- `currentEvidence`: observable artifacts, project events, feedback, implementation records, or tests already available. Record “none supplied” rather than inventing evidence.
- `targetLevel`: the explicit scope and autonomy expected, such as entrant portfolio, first-role/new-hire, junior contributor, or transition-ready contributor.
- `gaps`: competency claims not yet supported by current evidence.
- `learningTasks`: observable exercises tied one-to-one or many-to-one to gaps.
- `proofArtifacts`: inspectable outputs produced by those exercises.
- `tradeoffs`: time, access, dependency, transferability, and opportunity-cost differences.
- `uncertainties`: assumptions that need evidence before the path is preferred.

Each learning task must contain its own `feedbackCadence`, reviewer or feedback source, success criterion, and next review date. A cadence is actionable, for example “mentor review every Friday for four weeks,” not “get feedback regularly.”

## Gap-to-evidence chain

For every material gap, preserve this chain:

`gap → observable exercise → proof artifact → review criterion → feedbackCadence → next decision`

An exercise must expose game-design judgment, not only reading or tool familiarity. Useful evidence includes a testable rule specification, economy model with assumptions, playable prototype, annotated playtest record, implementation handoff, scoped content set, or decision log.

## Comparison rules

- Offer multiple plausible role paths and explicit tradeoffs when the target is uncertain.
- Keep paths provisional until evidence or user preference distinguishes them.
- Compare observable evidence, constraints, learning cost, and desired work. Never rank by age, education, major, background, employment gap, or prestige.
- Treat current employer demand, postings, projects, tools, compensation, hiring volume, and market outlook as time-sensitive. Use fresh primary research before attaching those claims to a path.
- Turn uncertainty into a verification task with an owner, source or exercise, and decision date.

## Completion check

A complete map makes the target level inspectable, connects every gap to practice and proof, defines task-level feedback timing, distinguishes evidence from inference, and leaves no hiring promise or fabricated candidate claim.
