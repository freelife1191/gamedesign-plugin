# Map Game Design Career

## Overview

Treat a career direction as an evidence-backed hypothesis. Produce multiple plausible role paths, explicit tradeoffs, and small verification tasks instead of declaring one correct career.

## Load Reference

Read `../../references/methods/role-map.md` before creating or revising a role map. Use its exact fields and task-level feedback contract.

## Map Paths

1. Record the candidate's stated constraints, interests, current artifacts, observable evidence, available time, and uncertainty. Mark absent material as a gap; never invent it.
2. Select at least two plausible role families when the target is not already fixed. Make every path provisional and state its opportunity cost, learning load, evidence strength, and uncertainty.
3. Set a concrete `targetLevel` for every path. Do not substitute vague labels such as “job ready.”
4. Compare current evidence with target competencies. Do not infer suitability from education, age, major, background, employment gaps, or prestige. Do not rank a path solely by education, age, major, or background; rank evidence-building options by observable evidence, constraints, and user goals.
5. Convert each material gap into an observable exercise, one or more proof artifacts, a review criterion, and a per-task `feedbackCadence`.
6. Add a verification task for uncertain interests, role assumptions, or current-market claims. Route time-sensitive employer, posting, project, tool, and market facts to `research-game-design-jobs` before using them.

## Output Contract

Return a role map using every field in the reference. Materialize the FAQ-facing matrix as the `competency-matrix` output and the ordered evidence-building plan as the `learning-roadmap` output. Keep facts, candidate statements, and inferences distinguishable. For each path, explain tradeoffs and identify the next smallest exercise that can strengthen or falsify the path.

## Completion

Finish when multiple paths or a justified fixed target are inspectable, each path has a `targetLevel`, every gap leads to an observable exercise and proof artifact, every learning task has its own `feedbackCadence`, and unsupported claims remain visible verification tasks. Never guarantee a job, hire, or career outcome.
