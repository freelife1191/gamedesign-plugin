# README 플러그인 소개 섹션 설계

## 문서 상태

- 작성일: 2026-08-12
- 상태: 사용자 승인
- 대상 문서: 저장소 루트 `README.md`와 주요 사용자 가이드 허브 3개
- 주요 독자: 게임 기획 입문자, 취업 준비생, 현업 기획자, 팀 리드, 교육자·멘토

## 결정 요약

루트 README의 목차 다음에 `플러그인 소개`를 새 H2로 추가한다. 소개는 제품 기능만 나열하지 않고 왜 만들었는지, 누구에게 맞는지, 어떤 자료를 참고했는지, 자료를 어떻게 검토·갱신하는지, 처음 어떤 질문으로 시작하면 좋은지를 한 흐름으로 설명한다.

개발 배경은 게임 기획자 유리링의 YouTube 채널과 저장소에 정리된 관련 리포트를 분명히 밝힌다. 다만 채널의 경험담이나 로컬 원문을 보편 법칙으로 소개하지 않는다. 원문 49편, 그중 유리링 관련 리포트 6편, 안정적인 실무 원칙 7개 영역, 2026-08-11에 확인한 현재 1차 자료 16건을 서로 다른 근거 층으로 설명한다.

## 목표

1. 처음 방문한 독자가 이 플러그인의 목적과 두 제품의 차이를 이해한다.
2. 자신에게 맞는 도구인지 빠르게 판단한다.
3. 한 문장으로 시작할 수 있는 질문 예시를 얻는다.
4. 플러그인이 참고하는 자료의 범위와 한계를 확인한다.
5. 경험담, 종합 원칙과 최신 외부 정보를 구별하는 근거 관리 방식을 이해한다.
6. 원문과 제3자 자료의 권리가 프로젝트 MIT License로 재허가되지 않는다는 경계를 확인한다.

## 비목표

- 유리링 채널의 전체 영상 목록이나 내용을 README에 복제하지 않는다.
- 로컬 리포트를 공식 영상 자막이나 채널 운영자의 검수본이라고 표현하지 않는다.
- 49개 원문을 현재의 보편적인 업계 표준으로 소개하지 않는다.
- 흥행, 매출, 채용 합격, 법률 준수나 사람 승인을 보장하지 않는다.
- 기존 설치·활용 사례·스킬·아키텍처 설명을 소개 섹션에 중복해서 옮기지 않는다.

## 정보 구조

`플러그인 소개`는 다음 순서를 사용한다.

1. `어떤 플러그인인가요?`: Studio와 Career의 역할, 기준 기획 결과물과 사람 검토 원칙
2. `왜 만들었나요?`: 흩어진 기획 지식을 실제 작업 순서와 검토 가능한 문서로 바꾸려는 개발 취지
3. `이런 분께 잘 맞습니다`: 학생, 취업 준비생, 현업 기획자, 팀 리드, 멘토
4. `이 플러그인으로 할 수 있는 일`: 설계, 검토, 포트폴리오·면접, 이미지·도식·내보내기 준비
5. `처음에는 이렇게 물어보세요`: Studio, Career와 연계 작업의 짧은 자연어 질문
6. `어떤 자료를 참고했나요?`: 유리링 관련 리포트와 전체 자료 범주·수량
7. `자료를 답으로 바꾸는 방식`: Source, Core, Current의 구분과 최신성·사람 승인 경계
8. `레퍼런스와 더 읽을 문서`: 채널, 로컬 원문 목록, 지식·근거 아키텍처, 인덱스와 현재 근거 등록부

## 표시 규칙

- 한국어 설명을 먼저 쓰고 영문 ID와 기술 용어는 필요한 곳에서만 보조 표기한다.
- 표는 대상 사용자와 근거 범주처럼 비교가 필요한 곳에만 사용한다.
- 루트 README와 세 가이드 허브의 모든 H2 바로 앞에 `---` 구분선을 둔다.
- 기존 H2 문구와 앵커는 유지하고, 문서 성격을 보여 주는 이모지는 안내문에만
  절제해서 사용한다.
- 루트와 전체 가이드는 `🧭`, Studio는 `🎮`, Career는 `🎓`를 대표 표식으로 쓴다.
- 유리링 채널은 개발의 주요 출발점 중 하나로 설명하며 유일한 근거라고 쓰지 않는다.
- 정확한 수량은 저장소의 기준 인덱스에서 파생한다.
- 질문 예시는 스킬 ID를 요구하지 않는 짧은 자연어 문장으로 쓴다.
- 출처의 한계와 사람 검토 책임을 소개 섹션 안에서 바로 밝힌다.

## 검증 기준

- README의 H2 순서는 `목차` 다음에 `플러그인 소개`가 오고 기존 섹션 순서를 유지한다.
- 목차에는 모든 H2가 정확히 한 번씩 같은 순서로 연결된다.
- 소개에 유리링 채널 URL, 원문 49편, 유리링 관련 리포트 6편, 7개 Core 문서, 현재 1차 자료 16건과 확인일 2026-08-11이 표시된다.
- 범주 수량은 Career 13, 재미·기획 의도 10, 시스템 13, 콘텐츠 10, 기획서 피드백 3으로 합계 49다.
- 루트 README와 세 가이드 허브는 모든 H2 앞의 구분선과 문서별 대표 이모지를
  유지한다.
- 로컬 근거 링크는 실제 파일 또는 문서 앵커로 해석되며 심볼릭 링크가 아니다.
- `node --test tests/contracts/root-readme-user-guides.test.mjs`, `npm run validate:guides`, `npm run validate:archify-catalog`, `git diff --check`가 통과한다.
